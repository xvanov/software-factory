## 1. Brittleness classes (why things break) — the mental model

Everything below is an instance of one of these. The factory is a big composed loop over
scattered state with many stand-ins for reality; brittleness clusters where a stand-in is trusted
or where detection isn't wired to remediation.

| # | Class | One-line |
|---|---|---|
| **B1** | **proxy ≠ real** | Trusting a stand-in — a recorded flag, a dry-run's unwritten intent, an `--auto` *enable*, a green test-run without a *commit*, a hardcoded `ci_state="success"`. Dominant class. |
| **B2** | **detect-without-remediate** | The factory detects well (escalations, stall detectors, tracker issues, CI signals) but remediation loops don't converge/complete → stale rot (open issues, stuck PRs, un-GC'd stories). |
| **B3** | **stale / poisoned state** | Live tree behind trunk; DB rows with invalid-enum values; "deployed" flags with no merge. State drifts from truth and nothing reconciles it. |
| **B4** | **silent detection failure** | Logic correct, substrate fails quietly (a truncatable slug suffix; a query returning None) → everything downstream no-ops with no error. |
| **B5** | **compose-bugs between fixes** | Independent fixes to shared control flow (merge/reconcile/dispatch) silently break each other. |
| **B6** | **unbounded / mis-bounded loops** | Composed dev/review/recovery/CI-fix loops with no aggregate ceiling, OR a "bound" that strands recoverable work. |
| **B7** | **verify-at-proxy-layer / reward-hack** | Gating on the layer the actor controls (dev owns tests) instead of an outcome oracle. |
| **B8** | **deploy / operational hygiene** | Surgical-deploy drift, live-tree ≠ trunk, manager not restarted, tick exit-code fragility. |
| **B9** | **app-coherence (loop-2/product)** | The PM/auditor spawns redundant/overlapping directions; a feature conflicts with the smoke journey. Not a factory-code bug — needs product/app judgment. |

## 6. Guardrails & gotchas (carry-over + new)

- **Method (non-negotiable):** scoped edit in a git worktree off `origin/main` → **INDEPENDENT
  adversarial reviewer** (make it try to break fail-safety) → real CI PR → squash-merge → surgical
  deploy (`git checkout origin/main -- factory/<files>` + restart `factory-manager.service` only
  if `factory/manager/**` changed) → run **full `uv run pytest -q`** before trusting green.
- **Verify live tree at session start:** `git diff origin/main -- factory/ tests/ | grep -c '^[+-]'`
  must be `0`. A handoff saying "deployed" does NOT guarantee the live tree is on that code (this
  session's #1 lesson).
- **"Services active" ≠ "sustains".** Check `systemctl --user show factory-tick@<app>.service -p
  Result -p ExecMainStatus` and the `errors=` line across recent runs.
- `factory/manager/**` and `bench/**` are FORBIDDEN to SELF-edit (DGM anti-gaming); operator may
  edit via a normal PR. All self-edit auto-merge surfaces stay staging-gated.
- `uv sync --all-extras` then prefix everything with `uv run`. A fresh worktree's venv may miss
  `croniter` etc. until `--all-extras`.
- `factory auto-merge` dry-run (the DEFAULT) still MUTATES the production DB. `factory resume` is
  OPERATOR-ONLY.
- `gh` quirks: `gh pr checks --json` fields vary by version; `_query_ci_state` works via `gh`.
- **Don't** hand-checkout a story branch in `/home/k/sacrifice` — the factory holds worktrees
  ("already used"); use a fresh clone.
- Spend cap $200/day; never stop the live factory; notify operator at $50/$75/$100 (org policy).
- DB backup before any hand-repair: `cp state/factory.db state/factory.db.bak-<ts>`.
