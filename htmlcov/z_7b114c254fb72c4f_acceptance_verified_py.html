1"""Gate: ``acceptance-verified`` (WS1.2 — independent acceptance oracle). 

2 

3The problem this closes 

4======================= 

5 

6Loop-4 makes the dev author AND run its own tests. That is great for 

7convergence, but a coder that writes the tests judging it can reward-hack — 

8special-case the exact assertions, weaken them, or delete the hard ones 

9(ImpossibleBench: hiding the acceptance tests from the coder drops cheating to 

10~0). Every other merge gate re-derives truth from artifacts the dev produced 

11(``tests-green`` re-runs the dev's suite; ``tests-meaningful`` scans the dev's 

12tests). None of them is INDEPENDENT of the dev. 

13 

14This gate is that independent layer. It runs an acceptance test authored from 

15the direction's acceptance criteria — the SPEC ONLY, blind to the dev's code 

16and the dev's tests — that the dev never sees or edits (authored at story spawn, 

17stored under ``state/acceptance/<app>/<story_id>/`` OUTSIDE the dev worktree; 

18see ``factory.chain.acceptance``). 

19 

20WHAT MAKES ITS GREEN MEAN SOMETHING (2026-08-05) 

21================================================ 

22 

23Running the oracle is not enough. Three properties have to hold or the green 

24carries no information, and none of them was checked when the gate first became 

25executable: 

26 

271. **The oracle must be able to FAIL.** ``normalize_oracle_source`` deliberately 

28 requires no ``assert``, and the vacuity check only catches skips — so 

29 ``def test_ac1(): assert True`` ran, reported "1 passed", and produced a 

30 merge-authoritative green against an implementation that violated the 

31 criterion. Closed by running the SAME oracle at the PR's MERGE BASE and 

32 requiring it to be RED there (PLAN A.6, ``factory.chain.red_green``), with 

33 ABLATION (``factory.chain.mutation.check_can_fail``) as the fallback when that 

34 base run yields no usable answer. 

35 

36 ⚠ THE CAVEAT — it lives in ``red_green``'s docstring and is repeated here 

37 because this is where it bites: only the *fails-at-base* half is oracle-free. 

38 Agentless measured 213/300 generated tests reproducing a bug but only 94/300 

39 also flipping green under the gold patch, so a hard both-halves gate rejects 

40 good work. Therefore "red at base" means AT LEAST ONE test failed there, and a 

41 base run that cannot be TRUSTED is ``unknown`` — a *skipped-with-reason*, 

42 which blocks and is never read as a pass (regression-only, never "approve"). 

43 

44 TWO MECHANISMS, ONE ORDER — and the order is the whole argument 

45 -------------------------------------------------------------- 

46 ``red_green.base_verdict`` asks *"is this oracle RED without the story's 

47 diff?"*. ``mutation.check_can_fail`` asks *"if we gut a symbol the diff 

48 touched, does the oracle go red?"*. They are not redundant and they are not 

49 interchangeable: **the base run is the STRONGER instrument**, so it always 

50 speaks first and its definitive answers are never overturned. 

51 

52 Why stronger: ablation is satisfied by an oracle that merely *calls* the code. 

53 ``def test(): client.post("/healthz"); assert True`` goes red under ablation 

54 (the gutted handler raises) while asserting nothing at all — whereas at the 

55 merge base that same oracle passes, which is the correct verdict "this carries 

56 no information about the diff". So ablation is used **only** where the base run 

57 returned ``unknown`` (no readable summary, timeout, nothing collected at base, 

58 the acceptance harness does not resolve at base — common for a story that 

59 CREATES the test directory). It is never allowed to rescue a base run that came 

60 back ``green``: ``green`` is a definitive "this oracle does not discriminate 

61 this diff", and the ablation of a diff symbol would answer a weaker question 

62 more permissively. That state stays a block with an operator waiver as its only 

63 path back. 

64 

65 The ``unknown`` state is also, by construction, not something the dev can 

66 steer into: the base run happens at the merge base, in a tree that predates the 

67 diff, under operator-owned app config. And the ablation fallback reproduces the 

68 primary path's structural defences in its own scratch clone — same channel 

69 rollback, plus a check that the clone really is the graded commit — so even a 

70 dev who could force ``unknown`` would gain nothing. 

71 

722. **The dev must not control the environment that judges it.** The old run 

73 happened in ``PRContext.repo_root`` — the story's own dev worktree — with 

74 pytest loading whatever ``conftest.py`` / ``pyproject.toml`` the diff put 

75 there. Two 7-line attacks forced a pass against a violating implementation (a 

76 ``pytest_runtest_call`` hookwrapper calling ``outcome.force_result(None)``, and 

77 ``addopts = "-p _fixup"`` plus a root plugin). Closed by running in a 

78 THROWAWAY git worktree (``red_green.judge_worktree``) — so nothing the dev left 

79 UNTRACKED exists there at all — in which the diff's own contribution to the 

80 oracle's import path is rolled back to the merge base. The oracle is never 

81 copied into the dev's tree, which also closes the leak window and the 

82 ``.pytest_cache`` disclosure. 

83 

84 PRODUCTION CODE FROM HEAD, THE WHOLE TEST SURFACE FROM BASE. That is the 

85 invariant, and it is wider than "collection channels" because restricting it to 

86 collection channels left a working forced-pass attack: the oracle is copied into 

87 the app's test directory, so pytest imports it as part of that package and runs 

88 ``backend/tests/__init__.py`` first — seven lines there rebind the function under 

89 test and a violating implementation goes green, with a RED merge-base run 

90 corroborating it (the file does not exist at base). ``__init__.py`` under 

91 ``tests/`` is test CODE, not a collection channel. The rollback set is therefore 

92 defined as the exact complement of ``factory.diff_paths.is_production_path``, so 

93 widening either underlying classifier widens it for free. 

94 

95 ⚠ ONE DOCUMENTED EXCEPTION TO THAT COMPLEMENT: ``pyproject.toml`` 

96 (2026-08-05). It is in the set as a pytest collection channel, and it is ALSO 

97 the dependency manifest the app's acceptance command resolves its environment 

98 from — sacrifice runs ``uv run --extra dev pytest`` with cwd ``backend``, and 

99 ``uv`` reads that exact file. Reverting it wholesale meant a story that ADDS a 

100 dependency, with a CORRECT implementation, got ``passed=False, 

101 authoritative=True`` for a collection error this gate caused itself, then got 

102 re-dispatched with an identical failure signature. So the file's two roles are 

103 split: **pytest tables from the merge base, every other table from HEAD** 

104 (``red_green.rollback_pytest_config_only``, which verifies both halves against 

105 ``tomllib`` and fails safe on any mismatch). The cost is real and is the reason 

106 this paragraph exists: the rollback set is no longer the clean complement of one 

107 predicate, so a reader widening either classifier must remember that this one 

108 file has its own handler. 

109 

110 Backing that up, because a residual case nobody thought of is the likelier 

111 failure than the one that was measured: an **errors-only red at HEAD is 

112 NON-authoritative whenever anything was rolled back**. A collection/import 

113 error after we rewrote the tree cannot be attributed — "the dev's code is wrong" 

114 and "we broke the environment" look identical — and a gate must never 

115 authoritatively blame the developer for what it may have done itself. It still 

116 blocks; it is just waivable and does not re-dispatch. An assertion that RAN and 

117 disagreed stays authoritative. 

118 

119 Still CONVENTIONAL, not structural: what gets restored is the app's own 

120 PREVIOUSLY MERGED test surface, which is dev-authored history — sacrifice's 

121 ``backend/tests/conftest.py:147`` overrides ``get_db`` with an autouse fixture 

122 and the shipped ``acceptance_harness_hint`` advertises that as a feature, so the 

123 oracle is judged against a dev-configured DB substitute. What IS structural: 

124 THIS story's diff cannot change it. 

125 

126 ⚠⚠ AND HERE IS WHAT THIS GATE DOES **NOT** GIVE YOU — READ BEFORE FLIPPING THE 

127 FLAG. This gate's green is bounded by "the diff's production code did not attack 

128 the harness", and **nothing checks that**. Measured 2026-08-05, three lines in 

129 the module under test: 

130 

131 import sys 

132 if 'pytest' in sys.modules: 

133 import _pytest.python 

134 _pytest.python.Function.runtest = lambda self: None 

135 

136 ...produces ``passed=True, verified=True, authoritative=True`` against an 

137 implementation that violates the criterion, with a genuinely RED merge-base run 

138 corroborating it. An ablation-AWARE variant of the same trick forges the fallback 

139 route too (detect the sentinel raise, forge red; otherwise forge green). 

140 

141 No rollback set closes this. The oracle must import the diff's production code to 

142 test it, so that code runs in the interpreter that computes the verdict, and 

143 in-process anything is defeatable in-process. The two candidate closures are 

144 (a) an out-of-process behavioural oracle — the verdict computed in the factory 

145 from HTTP responses, the way ``smoke-green`` already works — or (b) a 

146 tampering detector over the diff's production paths, which would false-block the 

147 ``factory`` app wholesale because its production code IS test infrastructure. 

148 Neither is built. See 

149 ``tests/…::test_KNOWN_OPEN_production_code_can_patch_pytest_in_process``, an 

150 ``xfail(strict=True)`` that turns red the day this is fixed. 

151 

1523. **The tree must be the merge candidate.** ``auto_merge._story_worktree`` 

153 resets to ``origin/<feature>`` only when ``git fetch`` returned 0, so on a 

154 fetch failure the gate graded whatever the worktree held — and could return an 

155 authoritative pass for an unrelated commit. The gate now requires 

156 ``pr.head_sha`` to be an ANCESTOR of the checkout's HEAD (not equal to it: the 

157 worktree merges ``origin/main`` in first, so equality would false-block) — AND 

158 that HEAD adds nothing over the PR head except the base branch 

159 (``red_green.extra_commits_beyond``). Ancestry alone still lets a worktree that 

160 is AHEAD of ``origin/<feature>`` — a commit the chain made and failed to push — 

161 pass as the merge candidate, which is the same fault one level in. Found by the 

162 adversarial pass on the fix for that fault. 

163 

164What "blocking" keys off 

165======================== 

166 

167Required-ness is a property of the APP, not of a database flag: once 

168``gates.acceptance_oracle`` is on, ``required_gate_labels`` requires this label 

169for every non-docs story, and THIS gate decides applicability. Per-story 

170expectation is re-derived from the spec by 

171``acceptance.acceptance_expected_for_story`` (flag → ref → the direction on 

172disk), because the flag is written by a best-effort DB write: a lost write used 

173to leave ``acceptance_expected=0`` on a story that must be gated, and both the 

174gate and the required set then read that as "no acceptance criteria, skip" and 

175shipped it un-gated. 

176 

177Resolution 

178========== 

179 

180* Not opted in (``gates.acceptance_oracle`` False): PASS (skip). Never required. 

181* Opted in, story genuinely has no acceptance criteria: PASS (not applicable). 

182* Opted in, expectation cannot be established (no story row, unresolvable 

183 direction): AUTHORITATIVE BLOCK — never a silent pass. 

184* Expected + stored test MISSING/unreadable (authoring flaked): AUTHORITATIVE 

185 BLOCK — the self-heal re-authors it, up to ``acceptance._MAX_AUTHOR_PASSES`` 

186 passes, after which it stays blocked and names the exhaustion. 

187* Dry-run / no checkout: NON-AUTHORITATIVE block (cannot verify), never a pass. 

188* Real run — three families, and only the first is a green: 

189 - **pass**: HEAD run green (≥1 passed, nothing failed, one readable summary) 

190 AND failability established — the base run RED 

191 (``failability_route="merge_base_red"``), or, when the base run was 

192 ``unknown``, an ablation of the diff's own production symbols that turned the 

193 oracle red (``failability_route="ablation"``). ``authoritative=True``, 

194 ``verified=True``. 

195 - **block**: the HEAD run failed a test assertion, or was vacuous. 

196 ``authoritative=True``. 

197 - **skipped-with-reason**: provenance unverified, no judge tree, no merge 

198 base, a collection channel we could not restore, conflicting summaries, an 

199 unreadable runner, an oracle that already passes at base, a base run we 

200 cannot trust, or an ERRORS-ONLY red at HEAD after we rolled anything back 

201 (``head_errors_after_environment_rollback`` — we perturbed the environment, 

202 so the error may be ours). ``passed=False``, ``authoritative=False``, ``verified=False`` 

203 — it blocks (fail-safe), does not blame the dev, is recorded for 

204 ``factory inbox``, and is the only family an operator waiver can clear 

205 (``acceptance.read_waiver`` — never a red HEAD run, never tampering, 

206 never the wrong commit). 

207* Any infrastructure error inside this gate: AUTHORITATIVE BLOCK. A raised 

208 exception here used to escape ``evaluate_all_gates`` and abort the entire merge 

209 evaluation. 

210"""

259# THIS interpreter, not a bare ``python`` resolved through PATH. 

260# 

261# The oracle authors Hypothesis PROPERTY tests from EARS-form acceptance criteria 

262# (WS4.3), so a generated test opens with ``from hypothesis import given`` — and 

263# ``hypothesis`` is a DEV EXTRA of this project. Bare ``python`` resolves through 

264# PATH to whatever the caller inherited; inside the dev sandbox that is a sibling 

265# app's venv (an interactive shell's rc file prepends it), which has no 

266# hypothesis. Collection then died with ModuleNotFoundError and the gate returned 

267# exit_code=2. 

268# 

269# That is a FALSE BLOCK, and an expensive one: the gate is required, so the story 

270# was re-dispatched to dev with an IDENTICAL failure signature until it exhausted 

271# its retries and sank to blocked_tests_need_clarification. Observed on stories 

272# 148 and 157 (2026-07-30); in both cases the dev's code was fine and the harness 

273# was broken. 

274# 

275# ``sys.executable`` is the fix rather than ``uv run``: the oracle runs the test in 

276# a bare temp directory with no ``pyproject.toml``, so ``uv run`` would find no 

277# project, build an ephemeral env, and still lack hypothesis. The interpreter 

278# already running the factory is by construction the one whose env satisfies the 

279# factory's own dev extras. 

280# 

281# It is only a DEFAULT, and for a real app it is usually the wrong one: an app 

282# whose deps are not in the factory's env MUST set ``acceptance_test_command`` 

283# (plus ``acceptance_test_dir`` / ``acceptance_test_cwd``) so the oracle runs in 

284# the app's own harness — and must then guarantee hypothesis in that env if any 

285# of its acceptance criteria are EARS-shaped. 

286# 

287# ``-B`` (no bytecode) plus ``-p no:cacheprovider`` keep the run from leaving a 

288# compiled copy of the hidden oracle or a ``.pytest_cache`` entry naming its 

289# tests. Both now land in a throwaway judge tree, but an app that overrides the 

290# command should keep the flags: ``.pytest_cache/v/cache/nodeids`` records the 

291# oracle's TEST NAMES and ``lastfailed`` records which of its assertions failed. 

292_DEFAULT_ACCEPTANCE_COMMAND = ( 

293 f"{sys.executable} -B -m pytest {{test_file}} -q -p no:cacheprovider" 

294)

297# The ablation fallback runs one oracle invocation per target, plus one baseline. 

298# Capped at 3 by the repo rule that nothing loops more than 3 times, and because 

299# the first target is the symbol the diff changed MOST — the marginal value of a 

300# fourth is small and the cost is another oracle run per tick. 

301_MAX_ABLATION_TARGETS = 3 

302# Matches ``evaluator._run_command``'s budget, deliberately: the ablation runs the 

303# SAME oracle command the HEAD run already completed inside, so anything much 

304# longer would only be waiting on a hang. 

305_ABLATION_TIMEOUT_S = 600 

306# HARD wall clock for the whole fallback, and it is not decoration. Each target 

307# costs a green baseline plus a mutant run, so three targets at the per-run budget 

308# is a 60-minute gate — inside ``evaluate_all_gates``, which has no timeout of its 

309# own, on a tick that other stories are queued behind. The per-run timeout is 

310# clamped to whatever is left, so this is the real bound, not a hint. Running out 

311# of budget is "not proven", i.e. the block stands. 

312_ABLATION_BUDGET_S = 900 

313# Below this there is no point starting another target: a run that cannot finish 

314# reports a timeout, which is an unattributable red, which is not a proof anyway. 

315_ABLATION_MIN_RUN_S = 30

331def _fmt_command(template: str, *, test_file: str) -> str: 

332 """Substitute ``{test_file}`` by literal replacement. 

333 

334 NOT ``str.format``: a template containing any other brace (a shell brace 

335 expansion, a jq filter) raised ``KeyError`` from inside the gate, and that 

336 exception escaped into ``evaluate_all_gates`` and killed the whole merge 

337 evaluation for the app rather than failing this one gate. 

338 """ 

339 return template.replace("{test_file}", test_file)

342def _resolve_subdir(repo_root: Path, rel: str | None, *, what: str) -> Path: 

343 """Resolve a repo-relative config path, refusing to escape the checkout.""" 

344 base = Path(repo_root).resolve() 

345 if not rel or not rel.strip(): 

346 return base 

347 target = (base / rel.strip()).resolve() 

348 if base != target and base not in target.parents: 

349 raise _ConfigError(f"{what}={rel!r} resolves outside the checkout ({target})") 

350 if not target.is_dir(): 

351 raise _ConfigError(f"{what}={rel!r} does not exist in the checkout ({target})") 

352 return target

355def _command_template(gates: AppGatesConfig) -> str: 

356 cmd_template = gates.acceptance_test_command or _DEFAULT_ACCEPTANCE_COMMAND 

357 if "{test_file}" not in cmd_template: 

358 # A command that never names the oracle does not run it. Exit 0 would then 

359 # be a green gate that verified nothing at all — the worst kind of 

360 # fail-open, produced by a single config typo. 

361 raise ValueError( 

362 "gates.acceptance_test_command must contain '{test_file}' " 

363 f"(got {cmd_template!r}) — a command that does not name the oracle " 

364 "cannot be evidence that it ran" 

365 ) 

366 return cmd_template

369def _oracle_test_file(gates: AppGatesConfig, dest_name: str) -> str: 

370 """Where the copied oracle sits, RELATIVE TO the configured run cwd. 

371 

372 Computed from the config strings only — never from a concrete tree — so the 

373 identical invocation replays in the judge worktree, at the merge base, and 

374 inside ``mutation.check_can_fail``'s scratch clone. ``os.path.relpath`` covers 

375 the case where the test dir is not under the cwd (dir=``backend/tests``, 

376 cwd=``backend/app`` ⇒ ``../tests/…``); the old code emitted an absolute path 

377 there, which is correct for exactly one tree and wrong for every other. 

378 """ 

379 d = (gates.acceptance_test_dir or "").strip() or "." 

380 c = (gates.acceptance_test_cwd or "").strip() or "." 

381 rel = os.path.relpath(os.path.join(d, dest_name), c) 

382 return PurePosixPath(Path(rel).as_posix()).as_posix()

385def _place_oracle( 

386 tree: Path, gates: AppGatesConfig, stored: Path, dest_name: str 

387) -> tuple[Path, Path]: 

388 """Copy the stored oracle into ``tree``; return ``(dest, run_cwd)``. 

389 

390 ``tree`` is always a THROWAWAY tree, never the dev's. Raises 

391 :class:`_ConfigError` when the configured dir/cwd does not resolve there — at 

392 the merge base that is an ordinary "cannot verify" rather than an infra fault, 

393 so the callers handle it differently. 

394 """ 

395 dest_dir = _resolve_subdir(tree, gates.acceptance_test_dir, what="acceptance_test_dir") 

396 run_cwd = _resolve_subdir(tree, gates.acceptance_test_cwd, what="acceptance_test_cwd") 

397 dest = dest_dir / dest_name 

398 if dest.is_symlink(): 

399 # ORACLE DISCLOSURE, found by the adversarial pass on the B2 fix (2026-08-05). 

400 # ``shutil.copyfile`` follows a symlink at the DESTINATION, so a diff that 

401 # commits ``<test_dir>/test_acceptance_oracle_<story id>.py`` as an ABSOLUTE 

402 # symlink into the dev's own worktree would have this gate write the hidden 

403 # oracle there — and the story id is guessable. A tracked file matching the 

404 # prefix is deliberately NOT treated as a leak (an app may legitimately commit 

405 # ``test_acceptance_oracle_smoke.py``; blocking on it was a permanent wedge), 

406 # so nothing upstream refuses this. Unlink first: the dev-blindness guarantee 

407 # is the whole point of the gate, and ``tree`` is always a throwaway. 

408 dest.unlink() 

409 shutil.copyfile(stored, dest) 

410 return dest, run_cwd

413def _run_oracle_in( 

414 tree: Path, gates: AppGatesConfig, stored: Path, dest_name: str 

415) -> _OracleRun: 

416 """Copy the stored oracle into ``tree`` and run the app's acceptance command.""" 

417 _dest, run_cwd = _place_oracle(tree, gates, stored, dest_name)

431 ``failed`` non-empty is *cannot verify*: a path we did not neutralise is still 

432 under the diff's control, and the caller must block on it non-authoritatively.

440 

441def _roll_back_environment( 

442 tree: Path, base_sha: str, plain: list[str], manifests: list[str] 

443) -> _Rollback: 

444 """PRODUCTION CODE FROM HEAD, THE WHOLE TEST SURFACE FROM BASE — in one place. 

445 

446 Called for BOTH judging trees (the judge worktree and the ablation clone), which 

447 is the point of the helper: when only the judge tree got a rollback fix, the 

448 ablation route silently ran under the diff's own collection config, and the 

449 fallback was weaker than the path it stands in for. 

450 

451 ``manifests`` are the paths that are ALSO the dependency manifest 

452 (``pyproject.toml``). They get the surgical treatment — pytest tables from the 

453 base, dependencies from HEAD — because reverting them wholesale broke every 

454 story that adds a dependency. See ``red_green.rollback_pytest_config_only``. 

455 """ 

456 restored, removed, failed = restore_paths_from(tree, base_sha, plain) 

457 neutralised: list[str] = [] 

458 for rel in manifests: 

459 ok, why = rollback_pytest_config_only(tree, base_sha, rel) 

460 if ok: 

461 neutralised.append(rel) 

462 else: 

463 failed.append(f"{rel} ({why})") 

464 return _Rollback( 

465 restored=restored, removed=removed, neutralised=neutralised, failed=failed 

466 )

469def _git_common_dir(repo_root: Path) -> Path | None: 

470 """The checkout's shared git dir (``.git``, or the worktree's parent gitdir).""" 

471 try: 

472 proc = subprocess.run( # noqa: S603,S607 - fixed argv, no shell 

473 ["git", "rev-parse", "--git-common-dir"], 

474 cwd=str(repo_root), 

475 capture_output=True, 

476 text=True, 

477 timeout=15, 

478 ) 

479 except (OSError, subprocess.SubprocessError): 

480 return None 

481 if proc.returncode != 0: 

482 return None 

483 out = proc.stdout.strip() 

484 if not out: 

485 return None 

486 p = Path(out) 

487 return p if p.is_absolute() else (Path(repo_root) / p)

490def _exclude_oracle_from_git(repo_root: Path) -> None: 

491 """Make a leaked oracle copy un-committable in this checkout. 

492 

493 Defense in depth for the independence guarantee. The oracle now runs in a 

494 throwaway judge tree, so the gate no longer writes into the dev's worktree at 

495 all — but a copy left by an OLDER factory build, or by any future path that 

496 runs in-tree, sits where the chain does a deterministic ``git add -A`` + 

497 commit on the dev's green pass (``handlers._commit_green_dev_work``), which 

498 would publish the hidden oracle into the PR. A local ``.git/info/exclude`` 

499 entry keeps ``add -A`` from staging it even then. Best-effort and local-only — 

500 never written to the repo tree. 

501 """ 

502 common = _git_common_dir(repo_root) 

503 if common is None: 

504 return 

505 try: 

506 info = common / "info" 

507 info.mkdir(parents=True, exist_ok=True) 

508 excl = info / "exclude" 

509 pattern = ORACLE_COPY_GLOB 

510 existing = excl.read_text(encoding="utf-8") if excl.exists() else "" 

511 if pattern in existing: 

512 return 

513 sep = "" if existing.endswith("\n") or not existing else "\n" 

514 excl.write_text( 

515 f"{existing}{sep}# factory acceptance oracle (never committed)\n{pattern}\n", 

516 encoding="utf-8", 

517 ) 

518 except OSError: 

519 return

542def _unverifiable( 

543 pr: PRContext, 

544 details: dict[str, object], 

545 *, 

546 kind: str, 

547 why: str, 

548 waiver_sha: str | None = None, 

549) -> GateResult: 

550 """SKIPPED-WITH-REASON: the oracle could not be graded, so we do not approve. 

551 

552 Blocks, but non-authoritatively: this is not evidence against the dev, it names 

553 the operator action, and it is recorded for ``factory inbox`` (a story stuck 

554 here sits at ``pr_open`` with no rejection reason and would otherwise appear in 

555 no operator surface at all). The one thing it must never be is a green — 

556 ``passed`` and ``verified`` are both False. 

557 

558 ``waiver_sha`` opts this state into the operator waiver 

559 (``acceptance.read_waiver``); pass ``None`` for states where a human must not 

560 be able to wave the story through (tampered evidence, the wrong commit). 

561 """ 

562 story = pr.story 

563 app = story.app if story is not None else "" 

564 sid = story.id if story is not None else None 

565 details = { 

566 **details, 

567 "authoritative": False, 

568 "verified": False, 

569 "unverifiable_kind": kind, 

570 } 

571 reason = f"acceptance oracle NOT VERIFIED ({kind}): {why}" 

572 

573 waiver = ( 

574 read_waiver(pr.software_factory_root, app, sid, for_oracle_sha=waiver_sha) 

575 if waiver_sha 

576 else None 

577 ) 

578 if waiver is not None: 

579 details["waived"] = True 

580 details["waiver"] = { 

581 "reason": str(waiver.get("reason"))[:300], 

582 "operator": str(waiver.get("operator")), 

583 "recorded_at": waiver.get("recorded_at"), 

584 } 

585 clear_gate_block(pr.software_factory_root, app, sid) 

586 return GateResult( 

587 label=_LABEL, 

588 passed=True, 

589 reason=( 

590 f"{reason} — cleared by an OPERATOR WAIVER " 

591 f"({str(waiver.get('reason'))[:120]}); the oracle did NOT verify this story" 

592 ), 

593 details=details, 

594 ) 

595 

596 record_gate_block(pr.software_factory_root, app, sid, kind=kind, reason=reason) 

597 return GateResult(label=_LABEL, passed=False, reason=reason, details=details)

600def _evaluate(pr: PRContext, app_config: AppConfig) -> GateResult: # noqa: PLR0911,PLR0912,PLR0915 

601 gates = app_config.gates 

602 

603 # Not opted in: skip (pass). Mirrors the optional command gates — a missing 

604 # capability means "this gate does not apply", not "this gate fails". 

605 if not gates.acceptance_oracle: 

606 return GateResult( 

607 label=_LABEL, 

608 passed=True, 

609 reason="acceptance oracle not enabled for this app (skipped)", 

610 details={"acceptance_oracle": False}, 

611 ) 

612 

613 story = pr.story 

614 ref = getattr(story, "acceptance_test_ref", None) if story is not None else None 

615 root = pr.software_factory_root 

616 

617 # Re-derived from the SPEC, never trusted from the DB flag alone. 

618 expected, source = acceptance_expected_for_story(story, app_config, root) 

619 if not expected: 

620 # Opted in, but this story has no acceptance criteria to verify — not 

621 # applicable. (Only ever reached when the direction was resolvable and 

622 # genuinely carries no criteria.) 

623 return GateResult( 

624 label=_LABEL, 

625 passed=True, 

626 reason="story has no acceptance criteria (not applicable, skipped)", 

627 details={ 

628 "acceptance_oracle": True, 

629 "acceptance_expected": False, 

630 "expected_source": source, 

631 }, 

632 ) 

633 

634 # Expected but the stored oracle is missing/unreadable → authoring flaked, or 

635 # there is no story row to author for at all. BLOCK AUTHORITATIVELY (never a 

636 # silent pass). The tick self-heal (reauthor_missing_oracles) re-authors it 

637 # before a later merge attempt, so this is not normally a dead-end; once the 

638 # authoring pass ceiling is exhausted it IS a dead-end that names itself. 

639 if not ref_is_readable(story, root): 

640 exhausted = author_exhausted(story, root) 

641 passes = ( 

642 author_passes(Path(root), story.app, story.id) 

643 if story is not None and root is not None 

644 else 0 

645 ) 

646 tail = ( 

647 " — authoring EXHAUSTED its pass ceiling; the operator must fix the " 

648 "direction's acceptance criteria or the app's acceptance harness config" 

649 if exhausted 

650 else " — authoring failed; blocking until it is re-authored (self-heals next tick)" 

651 ) 

652 return GateResult( 

653 label=_LABEL, 

654 passed=False, 

655 reason=( 

656 "acceptance oracle EXPECTED but not available " 

657 f"(ref={ref!r}, root={'set' if root else 'unset'}, " 

658 f"expected_source={source}){tail}" 

659 ), 

660 details={ 

661 "authoritative": True, 

662 "verified": False, 

663 "acceptance_expected": True, 

664 "acceptance_test_ref": ref, 

665 "expected_source": source, 

666 "author_passes": passes, 

667 "author_exhausted": exhausted, 

668 }, 

669 ) 

670 

671 # ref_is_readable(story, root) returned True above → story, ref, root all set. 

672 assert story is not None and ref is not None and root is not None 

673 

674 details: dict[str, object] = { 

675 "acceptance_test_ref": ref, 

676 "expected_source": source, 

677 } 

678 

679 # Need a real checkout to run against. Dry-run (no worktree) cannot 

680 # re-derive truth — never claim a merge-authoritative pass. 

681 if pr.dry_run or pr.repo_root is None: 

682 return GateResult( 

683 label=_LABEL, 

684 passed=False, 

685 reason="[dry-run] acceptance oracle present but not run (no checkout)", 

686 details={**details, "authoritative": False, "verified": False}, 

687 ) 

688 

689 repo_root = Path(pr.repo_root) 

690 p = Path(ref) 

691 stored = p if p.is_absolute() else Path(root) / p 

692 oracle_sha = oracle_sha256(stored.read_text(encoding="utf-8", errors="replace")) 

693 details["oracle_sha256"] = oracle_sha[:16] 

694 sid = story.id if story.id is not None else pr.head_sha 

695 dest_name = f"{ORACLE_COPY_PREFIX}{sid}.py" 

696 

697 # Validate the command template first: a broken template is an operator config 

698 # fault and must block AUTHORITATIVELY (it raises out to ``evaluate``), never 

699 # be mistaken for a run we merely could not read. 

700 cmd_template = _command_template(gates) 

701 

702 # Independence hygiene in the DEV worktree. The oracle no longer runs there, so 

703 # this only cleans up after older builds and interrupted runs — but a copy left 

704 # in the dev's tree is still a breach, so anything the sweep cannot remove 

705 # BLOCKS (the sweep now REFUSES to delete when git cannot say what is tracked). 

706 details["swept_before_run"] = sweep_leaked_oracles(repo_root) 

707 _exclude_oracle_from_git(repo_root) 

708 # Only a REAL leak blocks: an untracked copy (or a tree where git cannot say). 

709 # A git-TRACKED file matching the prefix is the app's own committed test, and 

710 # blocking on it was a permanent unwaivable wedge — see 

711 # ``acceptance.unremovable_oracle_leaks``. 

712 leaked = unremovable_oracle_leaks(repo_root) 

713 if leaked: 

714 return GateResult( 

715 label=_LABEL, 

716 passed=False, 

717 reason=( 

718 "acceptance oracle copies are present in the DEV worktree and could not be " 

719 f"removed ({leaked[:5]}) — blocking to protect dev-blindness" 

720 ), 

721 details={ 

722 **details, "authoritative": True, "verified": False, "leaked_copies": leaked, 

723 }, 

724 ) 

725 

726 # (3) PROVENANCE — grade the merge candidate or grade nothing. 

727 contains, why = head_contains_sha(repo_root, pr.head_sha) 

728 details["head_sha"] = pr.head_sha 

729 details["provenance"] = why 

730 if contains is not True: 

731 return _unverifiable( 

732 pr, details, 

733 kind="provenance_unverified" if contains is None else "wrong_commit", 

734 why=( 

735 f"the checkout does not demonstrably contain the PR head commit ({why}) — " 

736 "``_story_worktree`` only resets to origin/<feature> when git fetch " 

737 "returned 0, so an authoritative pass here could describe code that is " 

738 "not the one being merged" 

739 ), 

740 waiver_sha=None, # never waivable: this is not the merge candidate 

741 ) 

742 

743 # ...and nothing BEYOND the merge candidate. Ancestry alone allows a checkout 

744 # that is the PR head PLUS unpushed local commits, which is the same "grading 

745 # something other than what will merge" fault one level in. 

746 extra, how_extra = extra_commits_beyond(repo_root, pr.head_sha, pr.base_branch) 

747 details["provenance_extra"] = how_extra 

748 if extra is None or extra: 

749 details["extra_commits"] = extra[:5] if extra else None 

750 return _unverifiable( 

751 pr, details, 

752 kind="provenance_unverified" if extra is None else "checkout_ahead_of_pr_head", 

753 why=( 

754 f"the checkout carries work that is neither the PR head nor the base " 

755 f"branch ({how_extra}: {(extra or [])[:5]}) — an authoritative verdict " 

756 "here would describe code that is not being merged" 

757 if extra 

758 else f"could not establish that the checkout adds nothing to the PR head " 

759 f"({how_extra})" 

760 ), 

761 waiver_sha=None, # never waivable: this is not the merge candidate 

762 ) 

763 

764 base_sha, how = resolve_base_sha(repo_root, pr.base_branch) 

765 details["base_ref"] = how 

766 if base_sha is None: 

767 return _unverifiable( 

768 pr, details, kind="no_merge_base", 

769 why=f"cannot resolve the merge base ({how}), so the oracle's failability is unknown", 

770 waiver_sha=oracle_sha, 

771 ) 

772 details["base_sha"] = base_sha[:12] 

773 local_head = head_sha(repo_root) or "" 

774 details["checkout_head"] = local_head[:12] 

775 if base_sha == local_head: 

776 return _unverifiable( 

777 pr, details, kind="base_equals_head", 

778 why=( 

779 f"the merge base IS the checkout HEAD ({base_sha[:12]}) — there is no story " 

780 "diff here for the oracle to discriminate" 

781 ), 

782 waiver_sha=oracle_sha, 

783 ) 

784 

785 changed = changed_paths_since(repo_root, base_sha) 

786 if changed is None: 

787 return _unverifiable( 

788 pr, details, kind="diff_unreadable", 

789 why=f"git could not diff {base_sha[:12]}..HEAD in the checkout", 

790 waiver_sha=oracle_sha, 

791 ) 

792 # PRODUCTION CODE FROM HEAD, THE WHOLE TEST SURFACE FROM BASE. 

793 # 

794 # Restoring only ``is_collection_channel_path`` was not enough, and the gap was 

795 # a WORKING forced-pass attack (found 2026-08-05 by the adversarial pass on this 

796 # very fix, and the reason the set below is a union). The oracle is copied INTO 

797 # the app's test directory, so pytest's prepend import mode imports it as part of 

798 # that package — which executes ``backend/tests/__init__.py`` first. Seven lines 

799 # there (``import app.mod; app.mod.normalize_email = lambda e: e.lower()``) repair 

800 # a violating implementation before a single assertion runs. ``__init__.py`` under 

801 # ``tests/`` is test CODE, not a collection channel, so it was passed straight 

802 # through from HEAD — and the merge-base run went RED (the file does not exist at 

803 # base), so the forgery arrived wearing a perfect red→green. 

804 # 

805 # The general fact: every file in the test surface is in the oracle's import 

806 # path. Only production code may come from the diff. 

807 # 

808 # Expressed as the exact COMPLEMENT of ``is_production_path`` rather than as a 

809 # union of the two classifiers it is defined against 

810 # (``factory.diff_paths.is_production_path`` *is* 

811 # ``not is_test_code_path and not is_collection_channel_path``). Same set today, 

812 # but it stays correct for free: anything a future edit adds to either classifier 

813 # joins the rollback set automatically, instead of leaving a third place that 

814 # someone has to remember to widen. The ``__init__.py`` hole below is exactly 

815 # what forgetting costs. 

816 rollbacks = sorted({c for c in changed if not is_production_path(c)}) 

817 details["rolled_back_to_base"] = rollbacks 

818 details["collection_channels_in_diff"] = [ 

819 c for c in rollbacks if is_collection_channel_path(c) 

820 ] 

821 # ...except that ONE member of that set may not be reverted wholesale. 

822 # ``pyproject.toml`` is both a pytest collection channel and the DEPENDENCY 

823 # MANIFEST the app's acceptance command resolves its environment from, so 

824 # reverting it made every dependency-adding story fail collection and get blamed 

825 # for it. Its pytest tables come from the base; its dependencies come from HEAD. 

826 # This is the one documented exception to "the rollback set is the exact 

827 # complement of ``is_production_path``" — see 

828 # ``red_green.rollback_pytest_config_only`` for the measurement and the cost. 

829 manifests = [c for c in rollbacks if is_dependency_manifest(c)] 

830 plain = [c for c in rollbacks if not is_dependency_manifest(c)] 

831 details["dependency_manifests_in_diff"] = manifests 

832 

833 # (2) Run at HEAD in a THROWAWAY tree whose collection channels are rolled 

834 # back to the merge base, so the diff cannot decide its own verdict. 

835 with judge_worktree(repo_root, "HEAD", label="oracle-head") as (judge, err): 

836 if judge is None: 

837 return _unverifiable( 

838 pr, details, kind="no_judge_tree", 

839 why=( 

840 f"could not build the independent judge tree ({err}); running in the dev's " 

841 "own worktree would let the diff's conftest/pyproject force the verdict, " 

842 "which is the hole this gate exists to close" 

843 ), 

844 waiver_sha=oracle_sha, 

845 ) 

846 rolled = _roll_back_environment(judge, base_sha, plain, manifests) 

847 details["channels_restored"] = rolled.restored 

848 details["channels_removed"] = rolled.removed 

849 details["pytest_config_neutralised"] = rolled.neutralised 

850 if rolled.failed: 

851 return _unverifiable( 

852 pr, details, kind="channel_restore_failed", 

853 why=( 

854 f"could not restore collection channel(s) {rolled.failed!r} from the merge " 

855 "base; the diff would still control how the oracle is collected" 

856 ), 

857 waiver_sha=oracle_sha, 

858 ) 

859 head_run = _run_oracle_in(judge, gates, stored, dest_name) 

860 

861 details.update( 

862 { 

863 "command": head_run.command, 

864 "cwd": head_run.cwd, 

865 "test_file": head_run.test_file, 

866 "exit_code": head_run.exit_code, 

867 "output_tail": head_run.output, 

868 } 

869 ) 

870 status, summary = classify_pytest_run(head_run.exit_code, head_run.output) 

871 details["head_status"] = status 

872 # A count read from CONFLICTING summaries is not a count — one of the lines is 

873 # not pytest's. Recording it would republish the forgery as the gate's own 

874 # finding (``tests_passed: 7`` with zero real passes). 

875 details["tests_passed"] = ( 

876 summary.passed if summary is not None and status != "conflicting" else None 

877 ) 

878 if summary is not None: 

879 details["head_summary"] = summary.as_dict() 

880 

881 if status == "fail": 

882 # THE SAFETY NET (2026-08-05). We just rewrote the tree the oracle runs in — 

883 # the whole test surface reverted to the merge base, the manifest's pytest 

884 # tables with it. If the result is a COLLECTION/IMPORT error rather than a 

885 # test FAILURE, we cannot tell "the dev's code is wrong" from "we broke the 

886 # environment": an errors-only red is exactly what the reverted dependency 

887 # manifest produced, and an authoritative verdict there re-dispatched a dev 

888 # whose code was fine with an identical failure signature until the story 

889 # sank. So the block STANDS (fail-safe) but stops being an accusation — it is 

890 # waivable and it does not re-dispatch. 

891 # 

892 # Deliberately conditioned on a NON-EMPTY rollback set: with nothing rolled 

893 # back we perturbed nothing, the error is the artifact's own, and the dev is 

894 # the right party to tell. And an assertion that RAN and disagreed 

895 # (``summary.failed >= 1``) stays authoritative whatever we changed — that is 

896 # evidence about the code, not about the environment. 

897 # 

898 # This is belt-and-braces over the manifest fix above, not a substitute for 

899 # it: it bounds the residual cases nobody has thought of yet. 

900 errors_only = ( 

901 summary is not None and summary.failed == 0 and summary.errors >= 1 

902 ) 

903 if errors_only and rollbacks: 

904 return _unverifiable( 

905 pr, details, kind="head_errors_after_environment_rollback", 

906 why=( 

907 f"the oracle run at HEAD is red ENTIRELY from {summary.errors if summary else 0}" 

908 " error(s) and no test failure " 

909 f"(exit_code={head_run.exit_code}), and this gate rolled " 

910 f"{len(rollbacks)} path(s) back to the merge base to get an " 

911 "independent verdict — so we cannot distinguish a wrong " 

912 "implementation from an environment we perturbed ourselves. " 

913 "Blocking, but NOT as a finding against the story" 

914 ), 

915 waiver_sha=oracle_sha, 

916 ) 

917 return GateResult( 

918 label=_LABEL, 

919 passed=False, 

920 reason=f"ran independent acceptance oracle exit_code={head_run.exit_code}", 

921 details={**details, "authoritative": True, "verified": False}, 

922 ) 

923 if status == "vacuous": 

924 # A pytest run in which every test SKIPPED also exits 0 while verifying 

925 # nothing, and the persona is explicitly allowed to ``pytest.skip`` a 

926 # criterion that is untestable as written. 

927 return GateResult( 

928 label=_LABEL, 

929 passed=False, 

930 reason=( 

931 "acceptance oracle exited 0 but reported NO passing test " 

932 "(vacuous run — every criterion skipped, or nothing collected); " 

933 "blocking rather than crediting a verification that did not happen" 

934 ), 

935 details={**details, "authoritative": True, "verified": False}, 

936 ) 

937 if status == "conflicting": 

938 # Two DIFFERENT pytest summaries in one output; one of them is not 

939 # pytest's. A parser cannot decide which, so nothing here is gradeable. 

940 return _unverifiable( 

941 pr, details, kind="conflicting_summaries", 

942 why=( 

943 "the run printed more than one pytest summary — the pass count is forged or " 

944 "forgeable, so it cannot be evidence of anything" 

945 ), 

946 waiver_sha=None, # never waivable: the evidence itself is suspect 

947 ) 

948 if status == "unreadable": 

949 if "pytest" in head_run.command: 

950 return GateResult( 

951 label=_LABEL, 

952 passed=False, 

953 reason=( 

954 "acceptance oracle exited 0 but produced no pytest result summary " 

955 "(nothing ran, or the output was suppressed) — blocking rather than " 

956 "crediting a verification that cannot be evidenced" 

957 ), 

958 details={**details, "authoritative": True, "verified": False}, 

959 ) 

960 return _unverifiable( 

961 pr, details, kind="unreadable_runner", 

962 why=( 

963 f"the configured runner produced no readable test summary " 

964 f"(exit_code={head_run.exit_code}); an exit code alone cannot show that the " 

965 "oracle ran, let alone that it was able to fail" 

966 ), 

967 waiver_sha=oracle_sha, 

968 ) 

969 

970 # (1) The oracle passed at HEAD. Can it fail AT ALL? Run the same oracle at 

971 # the merge base; only a RED base licenses crediting this green. 

972 verdict, base_reason, base_details = _base_run( 

973 pr, gates, stored, dest_name, 

974 repo_root=repo_root, base_sha=base_sha, 

975 cmd_template=cmd_template, oracle_sha=oracle_sha, 

976 ) 

977 details["base_run"] = base_details 

978 if verdict == "green": 

979 return _unverifiable( 

980 pr, details, kind="oracle_not_discriminating", 

981 why=( 

982 f"{base_reason}. Its green at HEAD therefore says nothing about this story: " 

983 "a tautological oracle (``assert True``) and a criterion a sibling story " 

984 "already satisfied look identical from here. Re-author the oracle, tighten " 

985 "the direction's acceptance criteria, or record a decision with " 

986 "`factory acceptance-waive`" 

987 ), 

988 waiver_sha=oracle_sha, 

989 ) 

990 route = f"red at merge base {base_sha[:12]}, green at HEAD" 

991 if verdict == "unknown": 

992 # The base run could not be trusted. Fall back to ABLATION, which needs no 

993 # usable base: gut the production symbols this story's diff touched and 

994 # require the oracle to go red. See ``_ablation_can_fail``. 

995 proven, abl_reason, abl_details = _ablation_can_fail( 

996 gates, stored, dest_name, 

997 repo_root=repo_root, head_ref=local_head, 

998 base_sha=base_sha, plain=plain, manifests=manifests, 

999 cache_path=_cache_path(pr, "ablation_proofs.json"), oracle_sha=oracle_sha, 

1000 ) 

1001 details["failability_ablation"] = abl_details 

1002 if not proven: 

1003 return _unverifiable( 

1004 pr, details, kind="failability_unverified", 

1005 why=( 

1006 f"{base_reason}, and {abl_reason} — so a green at HEAD cannot be " 

1007 "distinguished from an oracle that cannot fail. Regression-only " 

1008 "fallback: NOT approving" 

1009 ), 

1010 waiver_sha=oracle_sha, 

1011 ) 

1012 route = f"failability proven by ablation ({abl_reason}); the merge-base run was unusable" 

1013 

1014 clear_gate_block(pr.software_factory_root, story.app, story.id) 

1015 return GateResult( 

1016 label=_LABEL, 

1017 passed=True, 

1018 reason=f"ran independent acceptance oracle exit_code={head_run.exit_code} ({route})", 

1019 details={ 

1020 **details, 

1021 "authoritative": True, 

1022 "verified": True, 

1023 "failability_route": "merge_base_red" if verdict == "red" else "ablation", 

1024 }, 

1025 )

1037def _ablation_can_fail( 

1038 gates: AppGatesConfig, 

1039 stored: Path, 

1040 dest_name: str, 

1041 *, 

1042 repo_root: Path, 

1043 head_ref: str, 

1044 base_sha: str, 

1045 plain: list[str], 

1046 manifests: list[str], 

1047 cache_path: Path | None = None, 

1048 oracle_sha: str = "", 

1049) -> tuple[bool, str, dict[str, object]]: 

1050 """SECOND route to failability: gut the story's own code, require the oracle to notice. 

1051 

1052 Reached only when the merge-base run came back ``unknown`` — see the module 

1053 docstring for why that is the only place it is allowed to speak. 

1054 

1055 Delegates to ``factory.chain.mutation.check_can_fail`` (PR #239), which 

1056 materializes its own scratch clone at ``head_ref``, demands a GREEN baseline, 

1057 splices a raise into ``path::qualname``, and returns ``True`` only for a red it 

1058 can attribute to that splice. Targets come from 

1059 ``mutation.select_symbols`` — the PRODUCTION functions this story's diff 

1060 actually touched, so a proof here says something about *this* story and not 

1061 just about the oracle in the abstract. 

1062 

1063 The ``prepare`` hook reproduces the primary path's structural defences inside 

1064 that clone: the hidden oracle is copied in (it exists in no repo), the diff's 

1065 whole test surface is rolled back to the merge base so a hostile ``conftest.py`` 

1066 or ``tests/__init__.py`` at HEAD cannot decide its own ablation verdict, and the 

1067 clone is confirmed to BE the graded commit. Without those, the fallback would be 

1068 weaker than the path it stands in for, and a dev who could steer the gate into 

1069 ``unknown`` would have found a way in. 

1070 

1071 CACHED on ``(head sha, oracle content, command, base sha)`` — B5. Every part is 

1072 immutable, which is the same argument the ``red`` base-verdict cache already 

1073 rests on: the graded commit does not change under a given sha, and the oracle is 

1074 frozen. Without it the route re-ran on every tick of every open PR (measured 

1075 1.45 s cold / 1.43 s warm on a toy repo, 15-30 s in a fresh clone and more for an 

1076 app with a DB container) — and the manifest fix above pushes MORE stories here, 

1077 because a dependency-adding story's base run cannot resolve the dependency it 

1078 adds and therefore comes back ``unknown``. 

1079 

1080 ``base_sha`` is in the key although the docstring's headline triple does not name 

1081 it: the rollback set and the ``prepare`` hook are both computed against the base, 

1082 so a proof is only about the tree that base produced. It costs no hit rate — a 

1083 checkout whose base moved has a different HEAD too. 

1084 

1085 Only a PROOF is cached. A ``False`` can be a timeout or an exhausted budget, and 

1086 freezing that would turn a fixable environment fault into a permanent block — 

1087 the same reason an ``unknown`` base verdict is never cached. 

1088 

1089 Returns ``(proven, reason, details)``. Every non-proof is ``False``. 

1090 """ 

1091 from factory.chain import mutation 

1092 

1093 attempts: list[dict[str, object]] = [] 

1094 out: dict[str, object] = {"route": "ablation", "attempts": attempts} 

1095 

1096 command = _fmt_command( 

1097 _command_template(gates), test_file=_oracle_test_file(gates, dest_name) 

1098 ) 

1099 out["command"] = command 

1100 

1101 # ``dir``/``cwd`` join the key for the same reason ``_base_run``'s key carries 

1102 # them: two configs can produce an identical relative ``{test_file}`` while 

1103 # running in different directories (dir=``a/tests``,cwd=``a`` and 

1104 # dir=``b/tests``,cwd=``b`` both yield ``tests/<name>``), and a proof is only 

1105 # about the harness that produced it. 

1106 key = run_key( 

1107 head_ref, oracle_sha, command, base_sha, 

1108 gates.acceptance_test_dir or "", gates.acceptance_test_cwd or "", 

1109 ) 

1110 if cache_path is not None: 

1111 hit = cache_get(cache_path, key) 

1112 if hit is not None and hit.get("proven") is True: 

1113 reason = f"{hit.get('reason', '')} [cached]" 

1114 return True, reason, {**hit, "reason": reason, "cached": True} 

1115 

1116 selection = mutation.select_symbols( 

1117 repo_root, base_sha, head_ref, max_symbols=_MAX_ABLATION_TARGETS 

1118 ) 

1119 if selection is None: 

1120 why = f"the diff {base_sha[:12]}..{head_ref} could not be read, so there is nothing to ablate" 

1121 out["reason"] = why 

1122 return False, why, out 

1123 symbols, candidates, notes = selection 

1124 out["candidates"] = candidates 

1125 if notes: 

1126 out["notes"] = notes[:5] 

1127 if not symbols: 

1128 why = ( 

1129 "the story's diff touches no production function that could be ablated, so the " 

1130 "oracle's failability cannot be established this way either" 

1131 ) 

1132 out["reason"] = why 

1133 return False, why, out 

1134 

1135 def _prepare(tree: Path) -> str | None: 

1136 # ``mutation._materialize_tree`` falls back to copying the WORKING TREE when 

1137 # it cannot clone, and a copy carries the dev's UNTRACKED files (a stray 

1138 # ``conftest.py``, a ``sitecustomize.py``) while carrying no ``.git`` — so 

1139 # the channel rollback below silently has nothing to roll back. Refuse 

1140 # anything that is not a real checkout at the commit we asked for. This is 

1141 # D2's property (grade the merge candidate or grade nothing) applied to the 

1142 # second tree; without it the fallback grades a tree nobody committed. 

1143 actual = head_sha(tree) 

1144 if actual != head_ref: 

1145 return ( 

1146 f"the scratch tree is at {actual!r}, not the graded commit " 

1147 f"{head_ref[:12]} — it is a working-tree copy or a wrong checkout, " 

1148 "and its collection config is not the merge candidate's" 

1149 ) 

1150 rolled = _roll_back_environment(tree, base_sha, plain, manifests) 

1151 if rolled.failed: 

1152 return ( 

1153 f"could not restore collection channel(s) {rolled.failed!r} from the merge " 

1154 "base — the diff would still control how the oracle is collected" 

1155 ) 

1156 try: 

1157 _place_oracle(tree, gates, stored, dest_name) 

1158 except (_ConfigError, OSError) as exc: 

1159 return f"the acceptance harness does not resolve in the scratch tree ({exc})" 

1160 return None 

1161 

1162 deadline = time.monotonic() + _ABLATION_BUDGET_S 

1163 for sym in symbols: 

1164 remaining = int(deadline - time.monotonic()) 

1165 if remaining < _ABLATION_MIN_RUN_S: 

1166 out["budget_exhausted_after"] = len(attempts) 

1167 break 

1168 proven, detail = mutation.check_can_fail( 

1169 repo_root=repo_root, 

1170 head_ref=head_ref, 

1171 target_path=sym.path, 

1172 qualname=sym.qualname, 

1173 check_command=command, 

1174 timeout_s=min(_ABLATION_TIMEOUT_S, remaining), 

1175 prepare=_prepare, 

1176 run_cwd=gates.acceptance_test_cwd, 

1177 ) 

1178 attempts.append({"symbol": sym.key, "proven": proven, "detail": detail[:300]}) 

1179 if proven: 

1180 out["proven_by"] = sym.key 

1181 out["reason"] = detail 

1182 if cache_path is not None: 

1183 cache_put( 

1184 cache_path, 

1185 key, 

1186 { 

1187 "proven": True, 

1188 "reason": detail[:300], 

1189 "proven_by": sym.key, 

1190 "route": "ablation", 

1191 "head_ref": head_ref[:12], 

1192 "base_sha": base_sha[:12], 

1193 }, 

1194 ) 

1195 return True, detail, out 

1196 

1197 why = ( 

1198 f"ablating {len(attempts)} of this story's own production symbol(s) " 

1199 f"({', '.join(str(a['symbol']) for a in attempts)}) never made the oracle go red" 

1200 if attempts 

1201 else f"the ablation fallback ran out of its {_ABLATION_BUDGET_S}s budget " 

1202 "before it could measure anything" 

1203 ) 

1204 out["reason"] = why 

1205 return False, why, out

1208def _base_run( 

1209 pr: PRContext, 

1210 gates: AppGatesConfig, 

1211 stored: Path, 

1212 dest_name: str, 

1213 *, 

1214 repo_root: Path, 

1215 base_sha: str, 

1216 cmd_template: str, 

1217 oracle_sha: str, 

1218) -> tuple[str, str, dict[str, object]]: 

1219 """Run the oracle at the merge base; ``(verdict, reason, details)``. 

1220 

1221 CACHED on ``(base sha, oracle content, command, dir, cwd)`` — everything the 

1222 result depends on. The base tree for a given sha is immutable and the oracle is 

1223 frozen, so re-running it on every tick of every open PR buys nothing. Only 

1224 DEFINITIVE verdicts (``red``/``green``) are cached: caching an ``unknown`` 

1225 would freeze a transient infra fault into a block that fixing the environment 

1226 could never clear. 

1227 """ 

1228 cache_path = _cache_path(pr, "base_runs.json") 

1229 key = run_key( 

1230 base_sha, oracle_sha, cmd_template, 

1231 gates.acceptance_test_dir or "", gates.acceptance_test_cwd or "", 

1232 ) 

1233 if cache_path is not None: 

1234 hit = cache_get(cache_path, key) 

1235 if hit is not None and hit.get("verdict") in {"red", "green"}: 

1236 return ( 

1237 str(hit["verdict"]), 

1238 f"{hit.get('reason', '')} [cached]", 

1239 {**hit, "cached": True}, 

1240 ) 

1241 

1242 with judge_worktree(repo_root, base_sha, label="oracle-base") as (base_tree, err): 

1243 if base_tree is None: 

1244 return "unknown", f"could not check out the merge base ({err})", { 

1245 "verdict": "unknown", "reason": err[:300], "base_sha": base_sha[:12], 

1246 } 

1247 try: 

1248 run = _run_oracle_in(base_tree, gates, stored, dest_name) 

1249 except _ConfigError as exc: 

1250 # e.g. ``acceptance_test_dir`` is a directory this story CREATES, so it 

1251 # does not exist at the base. Unknown, not red: "the harness could not 

1252 # run" is not "the test failed". 

1253 return "unknown", f"the acceptance config does not resolve at the base ({exc})", { 

1254 "verdict": "unknown", "reason": str(exc)[:300], "base_sha": base_sha[:12], 

1255 } 

1256 except OSError as exc: 

1257 return "unknown", f"the base run could not start ({exc})", { 

1258 "verdict": "unknown", "reason": repr(exc)[:300], "base_sha": base_sha[:12], 

1259 } 

1260 

1261 verdict, reason, summary = base_verdict(run.exit_code, run.output) 

1262 out: dict[str, object] = { 

1263 "verdict": verdict, 

1264 "reason": reason, 

1265 "base_sha": base_sha[:12], 

1266 "exit_code": run.exit_code, 

1267 "summary": summary.as_dict() if summary is not None else None, 

1268 "output_tail": run.output[-1500:], 

1269 } 

1270 if cache_path is not None and verdict in {"red", "green"}: 

1271 cache_put(cache_path, key, {k: v for k, v in out.items() if k != "output_tail"}) 

1272 return verdict, reason, out
