1"""Gate: ``tests-meaningful`` — static slop detection on the PR's test diff. 

2 

3The gate runs the slop detector against the changed test files; any finding 

4fails the merge. That is the whole gate, and it is the only thing this gate has 

5ever actually done. 

6 

7Why there is no mutation branch here any more 

8============================================= 

9This module used to carry a second, opt-in layer: real ablation/mutation 

10testing, behind ``gates.mutation_testing``. It **never ran** — the flag is 

11``false`` in every app config — while ``tests-meaningful`` IS in 

12``LOOP4_REQUIRED_GATE_LABELS``. That one flag was the only thing between four 

13independently verified defects and every merge in the factory: 

14 

151. **It ablated symbols the diff never touched.** It enumerated every public 

16 symbol of each changed file, capped the list at 5 and sorted by 

17 ``(path, lineno)`` — i.e. it took the top five of the alphabetically-first 

18 changed file. Verified here on ``e13d98e0``: 21 candidates, cap hit, and the 

19 five it picked had ZERO overlap with the 9 symbols the commit changed (7 of 

20 which it could never pick at all, being ``_``-prefixed). PLAN.md A.5 reports 

21 the same shape across the last 40 commits — median 21 candidates, 77% at the 

22 cap. 

232. **It was fail-OPEN.** ``factory.runner._run_pytest`` returns ``False`` for a 

24 600 s timeout, a missing command and a genuine test failure alike, and 

25 ``False`` was read as "the suite noticed → the symbol is exercised → good". 

26 With no green baseline before mutating, an already-red suite or a failed 

27 ``uv sync`` certified coverage that was never measured. Reproduced: with 

28 ``test_command`` pointing at a nonexistent binary the gate returned 

29 "ablation: all 2 sampled symbol(s) exercised by tests". 

303. **It mutated the live story worktree** — the ``state/worktrees/`` checkout 

31 the chain later pushes from — by round-tripping the whole file through 

32 ``ast.unparse`` (on ``handlers.py``: 4,804 → 2,113 lines, all 756 comments 

33 gone), restoring in a ``finally`` that a SIGKILL does not run. 

344. **It failed in dry-run**, which is the default for ``factory auto-merge``. 

35 

36The branch was DELETED rather than repaired in place. The repaired measurement 

37lives in ``factory/chain/mutation.py`` and is reachable only from 

38``factory mutation-score`` — deliberately not from any gate, so no merge 

39decision can reach it. An "advisory" branch inside a required gate is still one 

40edit from blocking every merge, and there is no measured case for gating on a 

41mutation score yet: the number it was meant to replace, the reviewer's 

42self-reported ``test_quality_score``, turned out to be inert (across all 31 

43reviewer calls of the graded n=19 sweep, no ``approve`` ever carried a score 

44below the 0.7 threshold, so the threshold vetoed nothing). 

45``evaluator.py:18-29`` set the precedent this follows — a gate detached from a 

46real check is worse than no gate. 

47 

48``gates.mutation_testing`` survives as a config field for compatibility and is 

49deliberately inert here. ``tests/test_gates_evaluation.py`` pins that: with the 

50flag ON, this gate's verdict and details are identical to the flag OFF. 

51""" 

52 

53from __future__ import annotations 

54 

55from factory.app_config import AppConfig 

56from factory.chain.gates.evaluator import GateResult, PRContext 

57from factory.chain.slop_detector import scan_diff 

58 

59 

60def evaluate(pr: PRContext, app_config: AppConfig) -> GateResult: 

61 label = "tests-meaningful" 

62 # Fail-closed, not vacuously-green: an empty ``files_changed`` on a REAL 

63 # real-run PR means the caller could not resolve the diff (a ``gh`` 

64 # failure), not that the diff is genuinely empty — ``scan_diff`` iterates 

65 # the file list, so an empty list scans nothing and reports "no findings" 

66 # regardless of what the PR actually did. Found 2026-08-07 alongside the 

67 # same hole in ``canonical-paths-only``: the tick path's synthesized 

68 # fixtures carried ``files_changed=[]`` for every real PR, so this REQUIRED 

69 # gate always passed without ever running. Dry-run / no-PR fixtures are 

70 # unaffected — that vacuous shape is genuinely what a preview with no 

71 # checkout looks like, not a resolution failure. 

72 if not pr.files_changed and not pr.dry_run and pr.pr_number > 0: 

73 return GateResult( 

74 label=label, 

75 passed=False, 

76 reason=( 

77 "cannot determine the changed files for this real PR " 

78 "(files_changed unavailable) — refusing to scan a diff it cannot see" 

79 ), 

80 details={"authoritative": False, "files_changed_unavailable": True}, 

81 ) 

82 findings = scan_diff(pr.files_changed, repo_root=pr.repo_root) 

83 findings_dicts = [fnd.as_dict() for fnd in findings] 

84 if findings: 

85 return GateResult( 

86 label=label, 

87 passed=False, 

88 reason=f"{len(findings)} slop finding(s)", 

89 details={"findings": findings_dicts}, 

90 ) 

91 

92 # ``mutation_status`` stays in the details for consumers that read the key, 

93 # and is now a constant. Note what is NOT here: any read of 

94 # ``app_config.gates.mutation_testing``. There is no expression in this 

95 # module through which that flag can change a merge verdict. 

96 return GateResult( 

97 label=label, 

98 passed=True, 

99 reason="no slop findings", 

100 details={"mutation_status": "not_a_merge_gate", "findings": []}, 

101 )
