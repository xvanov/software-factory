1"""Detector -> direction trigger, deduped on signature (019 AC7 / Flow D). 

2 

3The FMS L1 Watcher — deleted 2026-08-07 with the other three LLM tiers (see 

4``STATUS.md`` and the Exteroception v1 direction, P0) — was the *only* 

5production caller of ``factory.manager.detectors.DETECTORS``. This module is 

6their replacement caller: a plain chain-tick pass, no LLM in the loop, that 

7turns a detector firing into a machine-filed direction and stops the same 

8fault from being re-filed every tick (the "33x-re-file class" — the manager's 

9own measured 78% proposal redundancy). 

10 

11Design, top to bottom 

12---------------------- 

131. **Adapters, not raw calls.** Each of the 11 registered detectors returns a 

14 different shape (a list of findings, or a metrics dict) and most of them 

15 describe the *whole app pipeline*, not the one app this tick happens to be 

16 driving. ``_ADAPTERS`` maps detector name -> a small function that (a) 

17 invokes the detector with this tick's ``since``/lookback, (b) filters its 

18 output down to the rows that belong to ``app`` (a story-id -> app lookup 

19 via ``state/factory.db`` where the detector itself has no ``app`` field), 

20 and (c) reduces each surviving row to a *firing*: ``(subject, evidence)``, 

21 where ``subject`` is a STABLE entity name (a story id, a 

22 ``(story, persona)`` pair, a path, a state-transition triple) — never a 

23 timestamp or free text, because the subject feeds the dedupe signature. 

24 

25 Every adapter call is individually wrapped and its RETURN SHAPE is 

26 validated: a crashing detector, or one that returns something other than 

27 ``list[Firing]``, records an error and every OTHER detector still runs. 

28 ``_ADAPTERS`` is asserted (in tests) to cover exactly ``set(DETECTORS)`` — 

29 the failure this prevents is the deleted watcher's own: it hard-coded 9 of 

30 11 detectors and silently never called the other 2. 

31 

322. **Signature + dedupe.** ``f"{detector}:{normalize(subject)}"`` is embedded 

33 verbatim as ``<!-- detector-signature: {sig} -->`` in the filed direction's 

34 body (the ``ci_health`` pattern — see ``factory.chain.ci_health``). 

35 ``normalize`` maps internal whitespace to ``_`` (never a literal space — 

36 the marker-scan regex's capture group deliberately excludes whitespace, so 

37 a space inside a signature would make the marker permanently unreadable 

38 and re-file every tick forever; review round 2, S4). Before filing, this 

39 module scans the app's non-terminal directions for that marker. Unlike 

40 ``ci_health``, a scan FAILURE here refuses to file rather than falling 

41 through to "not open" — ``ci_health`` gates exactly one signature per app, 

42 so failing open there costs at most one duplicate; this module fans out 

43 across 11 detectors, and failing open on a broken scan is precisely the 

44 re-file storm this whole mechanism exists to prevent. Fail SAFE means 

45 blocking new filings, never re-filing on a dedupe blind spot. A direction 

46 directory with no readable ``direction.md`` (e.g. a partial write left 

47 behind by a disk-full ``create_direction`` call) makes the whole scan 

48 untrustworthy and is treated the same way (S3). 

49 

50 Dedupe-terminal policy (S9): a direction status of ``closed`` is ALSO 

51 terminal for this scan (a superset of the shared 

52 ``factory.chain.scheduled_tasks._TERMINAL_DIRECTION_STATUSES``, kept LOCAL 

53 to this module rather than edited into that shared constant — see the 

54 docstring on ``_open_detector_signatures``). Once an operator explicitly 

55 closes a detector-filed direction, its signature is free to fire again: 

56 ``factory/manager/gc.py`` only reaps ``scheduled-`` sources, so a 

57 ``detector-*`` direction is never garbage-collected, and treating 

58 ``closed`` as non-terminal-forever would mean the ONLY way out of the 

59 inbox is permanent silence. This is safe only combined with the S1 

60 liveness/recency fix below — without it, a still-firing-on-stale-evidence 

61 direction that gets closed would immediately re-file (the exact 

62 abandoned<->refile ping-pong the first review round measured). 

63 

643. **A hard cap, priority-ordered.** At most ``_MAX_FILINGS_PER_TICK`` (3) new 

65 directions per tick, across every detector combined — CLAUDE.md's 

66 "nothing loops more than 3 times" applied to self-filed work. Firings 

67 beyond the cap are reported, not dropped: dedupe means they file on a 

68 LATER tick once the cap has headroom. Firings are round-robined across 

69 detectors by ``_DETECTOR_PRIORITY`` before the cap is applied (S7) — a 

70 detector with no floor (formerly ``runs_failed_since``) enumerating first 

71 and ALWAYS having something to report must never be able to monopolize 

72 the cap and starve a wedge-detecting signal like ``stalled_stories`` 

73 indefinitely (measured: 4 consecutive ticks filed nothing else). 

74 

754. **Operator-gated filing.** Every filed direction carries 

76 ``source=f"detector-{name}"``. That source is not in 

77 ``factory.directions.approval._DETERMINISTIC_SOURCES`` (unlike 

78 ``ci-health``, which fires on an objective external fact — a required 

79 check went red), so ``requires_operator_approval`` parks every detector 

80 filing until ``factory approve-direction`` — spend on self-improvement 

81 stays operator-ratified (Flow D step 4). 

82 

835. **A built-in, category-shaped acceptance criterion (S5).** Every filed 

84 direction sets ``explore=True`` (S2) — the built-in criteria below ARE the 

85 spec, but ``factory.backpressure.validator.validate_direction``'s 

86 sufficiency check (``has_flow or has_api_spec or explore_tag``) never 

87 inspects criteria quality at all, so ``explore=False`` measured 

88 ``is_valid=False, severity=blocking`` for every real filing (no 

89 user_flow, no api_spec) and, end to end, ``pm_sync`` parked every one at 

90 ``needs-direction`` even after a real operator approval — 

91 detect-without-remediate at full filing volume. ``ci_health.py`` sets 

92 ``explore=True`` for exactly this shape of direction; the vacuity gate is 

93 the ONLY thing ``explore=True`` bypasses, and it still runs (see below). 

94 

95 The criterion wording is DETECTOR-SHAPE-SPECIFIC, not one template, 

96 because a single "the detector goes quiet for N ticks" template is 

97 auto-satisfied by construction for the ``since``-windowed detectors: 

98 ``_mark_ran`` advances the per-app marker every tick regardless of 

99 outcome, so old evidence has already scrolled out of the window on the 

100 very next look, with nothing fixed. Three shapes: 

101 

102 * **event-shaped** (``retry_storm``, ``placeholder_prompts``, 

103 ``conformance_breach``, ``tick_duration_outliers``, the inert 

104 ``runs_failed_since``): the evidence is a specific PAST event, so the 

105 criterion is anchored to a fixed point in time (the filing moment) — 

106 "no NEW finding with a timestamp after `fired_at`" — which a later scan 

107 merely advancing past the old evidence cannot satisfy. 

108 * **liveness-shaped** (``review_churn``, ``state_distribution_skew``, 

109 ``stalled_stories``, ``worktree_orphans``): the evidence describes an 

110 ONGOING condition on a still-live subject; the criterion is "the subject 

111 reaches a state where the detector no longer classifies it as 

112 live/anomalous" — satisfiable by actually fixing/advancing the subject, 

113 not by inaction, because the S1 liveness fix (below) means the detector 

114 keeps firing on unfixed, still-live evidence across repeated ticks. 

115 * **metric-shaped** (``cost_spike``, ``fms_yield``): the evidence is a 

116 factory-wide RATE; the criterion is "the rate returns to baseline". 

117 

118 ``tests/test_detector_watch.py`` asserts the exact generated text 

119 classifies ``positive-observable`` against the real vacuity gate, that a 

120 real filed direction passes ``validate_direction`` (the check that would 

121 have caught S2), and that the liveness-shaped criterion is NOT 

122 auto-satisfied by calling the pass twice against unfixed state. 

123 

1246. **Liveness + recency scoping (S1).** ``review_churn`` deliberately ignores 

125 its ``since`` argument for the cumulative cycle counts (see that 

126 detector's own docstring) and ``state_distribution_skew`` computes its 

127 skew fraction over EVERY state including ``deployed`` — a fully-shipped 

128 backlog reads as "74% skewed toward deployed". Against live state, this 

129 filed 46 directions: 44 ``review_churn`` firings on stories that had 

130 already shipped weeks ago, plus one ``state_distribution_skew`` firing per 

131 app for the same reason. Both adapters now require: (a) the subject is 

132 CURRENTLY live (``review_churn``'s ``active_in_window`` computed against a 

133 fixed ``_LIVENESS_LOOKBACK`` from *now* — deliberately NOT the pass-to-pass 

134 marker, which would let two consecutive ticks with nothing fixed flip a 

135 still-current signal to "not live" purely because the marker advanced), 

136 and (b) the story/skew is computed over NON-TERMINAL states only. 

137"""

233class _StoryLookupError(RuntimeError): 

234 """A genuine failure to query ``state/factory.db`` (locked, corrupt, 

235 unreadable) — distinct from "story not found", which is a normal, 

236 expected outcome (S10, review round 2). Left uncaught by every adapter 

237 that can raise it, so it propagates to ``detector_watch_tick``'s 

238 per-detector wrapper and is recorded as an error there: that detector is 

239 NOT marked as having cleanly run. Swallowing a lock-contention or 

240 corrupt-DB error as "story not found" would silently go dark on real 

241 data (CLAUDE.md failure class 3: silent detection failure) instead of 

242 surfacing it. 

243 """

246def _story_row(root: Path, story_id: int | None) -> tuple[str, str] | None: 

247 """Return ``(app, state)`` for ``story_id``. 

248 

249 ``None`` means "no such story" (or no DB file at all) — a normal outcome 

250 the caller should just skip. Raises :class:`_StoryLookupError` on any 

251 DB-level failure; callers must NOT treat that the same as "not found". 

252 """ 

253 if story_id is None: 

254 return None 

255 db_path = root / "state" / "factory.db" 

256 if not db_path.exists(): 

257 return None 

258 try: 

259 conn = sqlite3.connect(str(db_path)) 

260 try: 

261 row = conn.execute( 

262 "SELECT app, state FROM stories WHERE id = ?", (story_id,) 

263 ).fetchone() 

264 finally: 

265 conn.close() 

266 except sqlite3.Error as exc: 

267 raise _StoryLookupError(repr(exc)) from exc 

268 if row is None or row[0] is None: 

269 return None 

270 return (str(row[0]), str(row[1]))

464 branch below is structurally near-inert under ``ctx.since`` — a short,

472 (stuck-tick) branch below is a live sensor; do not advertise the

480 if str(row.get("app") or "") != ctx.app: 

481 continue 

482 tick_id = str(row.get("tick_id") or "") 

483 if not tick_id: 

484 continue 

485 firings.append(Firing(subject=f"tick-outlier:{tick_id}", evidence=row))

490 firings.append(

493 evidence={"still_running": stuck, "still_running_max_age_s": max_age}, 

494 )

496 return firings

504# re-measurement still fired once on ``sacrifice`` — 2 non-terminal stories, 

505# BOTH in ``deploy_pending``, a fraction of 2/2 = 1.0. That is arithmetic, not 

506# a skew: below a handful of open stories, ANY single-state backlog trivially 

507# "exceeds" 0.5 with nothing anomalous behind it (1/1, 2/2, 2/3 all clear the 

508# threshold on pure chance). 5 is chosen because it is the smallest N at which 

509# the >0.5 fraction predicate first requires an ACTUAL majority (>=3 of 5) 

510# rather than being satisfiable by every story just happening to share one 

511# state — at N<5 (1,2,3,4) a fraction >0.5 is reachable with as few as 1-3 

512# stories in ONE state versus the rest split arbitrarily, which is exactly 

513# the "not enough data to call it a skew" case this floor exists to exclude. 

514_STATE_SKEW_MIN_NON_TERMINAL_SAMPLE = 5

517def _adapter_state_distribution_skew(ctx: _AdapterCtx) -> list[Firing]: 

518 from factory.manager.detectors import state_distribution_skew as _detector 

519 from factory.manager.detectors.stalled_stories import ( 

520 _TERMINAL_STATES as _terminal_story_states, 

521 ) 

522 

523 # ``liveness_since`` (not ``since``): the snapshot-recency filter asks 

524 # "is this snapshot still CURRENT", not "what's new since I last looked" 

525 # — using the pass-to-pass marker here risked excluding a still-valid, 

526 # still-most-recent snapshot purely because the marker outran its 

527 # timestamp between two ticks with nothing new written (S1/S5). 

528 metrics = _detector(root=ctx.root, since=ctx.liveness_since) 

529 snap = (metrics.get("app_snapshots") or {}).get(ctx.app) 

530 if not snap: 

531 return [] 

532 counts: dict[str, int] = snap.get("counts_by_state") or {} 

533 # The detector's own ``exceeds_threshold``/``exceeds_state`` fields are 

534 # computed over ALL states including terminal ones — a backlog that is 

535 # 74% ``deployed`` (fully shipped) reads as "skewed" by that math. Ignore 

536 # those fields entirely and recompute over non-terminal states only. 

537 non_terminal = {s: c for s, c in counts.items() if s not in _terminal_story_states} 

538 total = sum(non_terminal.values()) 

539 if total == 0: 

540 # Every open story is terminal (fully shipped or fully closed) — 

541 # nothing "skewed" about that. 

542 return [] 

543 if total < _STATE_SKEW_MIN_NON_TERMINAL_SAMPLE: 

544 # Too few open stories for a fraction to mean anything — see the 

545 # constant's comment above (review round 3 fix for the residual 

546 # small-N firing the round-2 live re-measurement found). 

547 return [] 

548 max_state = max(non_terminal, key=lambda s: non_terminal[s]) 

549 max_fraction = non_terminal[max_state] / total 

550 if max_fraction <= _STATE_SKEW_THRESHOLD_FRACTION: 

551 return [] 

552 evidence = { 

553 "ts": snap.get("ts"), 

554 "counts_by_state_non_terminal": non_terminal, 

555 "total_non_terminal": total, 

556 "max_state": max_state, 

557 "max_fraction": round(max_fraction, 4), 

558 } 

559 return [Firing(subject=f"state-skew:{max_state}", evidence=evidence)]

654def _priority_ordered_firings( 

655 all_firings: list[tuple[str, Firing]], 

656) -> list[tuple[str, Firing]]: 

657 """Round-robin across detectors, highest-priority tier first (S7). 

658 

659 With plain insertion order, whichever detector happens to enumerate 

660 first in ``_ADAPTERS`` — and ALWAYS has something to report — ate the 

661 entire per-tick filing cap every single tick, starving every other 

662 detector indefinitely (measured: 4 consecutive ticks filed nothing but 

663 ``runs_failed_since``, before that detector was made inert — S8). This 

664 round-robins one firing from each detector, ordered by 

665 ``_DETECTOR_PRIORITY`` (ties broken by name), so no single chatty source 

666 can ever monopolize the cap. 

667 """ 

668 by_detector: dict[str, list[Firing]] = {} 

669 for name, firing in all_firings: 

670 by_detector.setdefault(name, []).append(firing) 

671 

672 ordered_names = sorted( 

673 by_detector, key=lambda n: (_DETECTOR_PRIORITY.get(n, _DEFAULT_DETECTOR_PRIORITY), n) 

674 ) 

675 queues = {n: list(v) for n, v in by_detector.items()} 

676 ordered: list[tuple[str, Firing]] = [] 

677 while any(queues[n] for n in ordered_names): 

678 for n in ordered_names: 

679 if queues[n]: 

680 ordered.append((n, queues[n].pop(0))) 

681 return ordered

726# Collapse anything that would otherwise let a subject break out of the 

727# HTML-comment marker syntax (a literal "-->" or ">" inside a path/subject

729_VOLATILE_WS_RE = re.compile(r"\s+") 

730_COMMENT_UNSAFE_RE = re.compile(r"-{2,}|>")

733def _normalize_subject(subject: str) -> str: 

734 # S4 (review round 2): internal whitespace maps to "_", NEVER a literal 

735 # space. ``_SIGNATURE_MARKER_RE``'s capture group is ``[^\s>]+`` 

736 # (whitespace is deliberately excluded — the marker syntax itself has 

737 # significant surrounding whitespace), so a signature containing an 

738 # internal space could never be read back out of its own marker: the 

739 # scan would always see "not open" and re-file every tick, forever. A 

740 # worktree path with a space, or any non-str value that stringifies with 

741 # one, reaches this. Underscore has no such collision. 

742 s = _VOLATILE_WS_RE.sub("_", subject.strip().lower()) 

743 s = _COMMENT_UNSAFE_RE.sub("_", s) 

744 return s[:_MAX_SUBJECT_LEN]

759def _open_detector_signatures(app: str, root: Path) -> set[str]: 

760 """Signatures already carried by a non-terminal direction for ``app``. 

761 

762 Mirrors ``factory.chain.ci_health._has_open_ci_health_direction``'s scan 

763 shape, with two deliberate divergences: 

764 

765 * **Dedupe-terminal policy (S9).** A direction status of ``closed`` is 

766 ALSO terminal here — a LOCAL superset of the shared 

767 ``factory.chain.scheduled_tasks._TERMINAL_DIRECTION_STATUSES``, not an 

768 edit to that shared constant (CLAUDE.md: "fixes to shared control flow 

769 do not compose for free" — every OTHER duplicate-detection scan in the 

770 chain reads that constant too). Once an operator explicitly closes a 

771 detector-filed direction, its signature is free to fire again: 

772 ``factory/manager/gc.py`` only reaps ``scheduled-`` sources, so a 

773 ``detector-*`` direction is never garbage-collected, and without this, 

774 "closed" would be the only way out of the inbox and it would mean 

775 "silenced forever". Safe only combined with the S1 liveness fix — see 

776 the module docstring. 

777 * **Orphan dirs are a scan failure, not an absence (S3).** A direction 

778 directory with NO ``direction.md`` at all (e.g. a partial write left 

779 behind by a disk-full ``create_direction`` call before this review 

780 round's cleanup fix, or any other cause) makes the WHOLE scan 

781 untrustworthy — we cannot tell whether it once carried an open 

782 signature — so this RAISES rather than silently skipping it. The 

783 caller treats any exception here as a dedupe-scan failure and refuses 

784 to file (never a storm of invisible orphan dirs). A single malformed 

785 but PRESENT ``direction.md`` (bad frontmatter, corrupt YAML) is still 

786 swallowed per-directory — one bad sibling must not blind the scan to 

787 every other one. 

788 """ 

789 import frontmatter as _frontmatter 

790 import yaml as _yaml 

791 

792 from factory.chain.scheduled_tasks import _TERMINAL_DIRECTION_STATUSES 

793 

794 terminal = _TERMINAL_DIRECTION_STATUSES | {"closed"} 

795 

796 directions_dir = Path(root) / "apps" / app / "directions" 

797 found: set[str] = set() 

798 if not directions_dir.is_dir(): 

799 return found 

800 for d in directions_dir.iterdir(): 

801 if not d.is_dir(): 

802 continue 

803 md = d / "direction.md" 

804 if not md.is_file(): 

805 raise RuntimeError( 

806 f"direction dir has no direction.md (scan untrustworthy): {d}" 

807 ) 

808 try: 

809 post = _frontmatter.load(str(md)) 

810 status = "created" 

811 state_path = d / "state.yaml" 

812 if state_path.is_file(): 

813 state = _yaml.safe_load(state_path.read_text(encoding="utf-8")) or {} 

814 status = str(state.get("status", "created")) 

815 if status in terminal: 

816 continue 

817 content = str(getattr(post, "content", "") or "") 

818 found.update(_SIGNATURE_MARKER_RE.findall(content)) 

819 except Exception: # noqa: BLE001 - one bad-but-PRESENT sibling must not blind the scan 

820 continue 

821 return found

985 

986def detector_watch_tick( 

987 software_factory_root: Path, 

988 app: str, 

989 *, 

990 now: datetime | None = None, 

991) -> DetectorWatchResult: 

992 """Run every registered detector once for ``app`` and file/dedupe firings. 

993 

994 Never raises: every detector call (including a wrong-shaped return — S6), 

995 the dedupe scan, and every direction write are individually wrapped so a 

996 single failure degrades this pass (recorded in 

997 ``DetectorWatchResult.errors``) without ever breaking the caller's tick. 

998 Callers (``factory.chain.orchestrator.tick``) are expected to 

999 additionally skip calling this entirely in ``dry_run`` and in modes that 

1000 suppress forward motion (``paused``, ``drain-reviews``) — this function 

1001 does not gate on either itself. 

1002 """ 

1003 root = Path(software_factory_root) 

1004 now = now or datetime.now(UTC) 

1005 since = _last_since(root, app, now=now) 

1006 liveness_since = now - _LIVENESS_LOOKBACK 

1007 result = DetectorWatchResult(app=app) 

1008 

1009 ctx = _AdapterCtx(root=root, app=app, since=since, liveness_since=liveness_since) 

1010 all_firings: list[tuple[str, Firing]] = [] 

1011 for name, adapter in _ADAPTERS.items(): 

1012 t0 = _time.monotonic() 

1013 try: 

1014 raw = adapter(ctx) 

1015 except Exception as exc: # noqa: BLE001 - one crashing detector must never break the pass 

1016 result.errors.append((name, repr(exc))) 

1017 continue 

1018 elapsed = _time.monotonic() - t0 

1019 if elapsed > _SOFT_DEADLINE_S: 

1020 result.errors.append((name, f"soft_deadline_exceeded: {elapsed:.1f}s")) 

1021 # S6 (review round 2): validate the return SHAPE before trusting it — 

1022 # a wrong-shaped return (None, a str, a list of non-Firing elements) 

1023 # used to raise past this point and discard the WHOLE pass, including 

1024 # every other, healthy detector. 

1025 if not isinstance(raw, list): 

1026 result.errors.append( 

1027 (name, f"non-list return from adapter: {type(raw).__name__}") 

1028 ) 

1029 continue 

1030 bad_types = sorted({type(x).__name__ for x in raw if not isinstance(x, Firing)})
