1"""Idle becomes a ping (019 AC6 / Flow C). 

2 

3``factory/chain/idle.py`` (deleted 2026-08-07, 019 AC5) detected a drained app 

4and rotated through scanner personas to manufacture more work — it fired 957 

5times and reached a human zero times. This module replaces that whole shape: 

6when an app has no dispatchable work and no live human-filed direction, it 

7writes exactly ONE deduplicated ``operator_ping`` per **idle episode** and 

8files NO machine-authored direction. The operator decides what happens next 

9(file a direction, or ignore it). 

10 

11Idle episode, precisely 

12------------------------ 

13An idle episode STARTS the first tick where both hold: 

14 

15 * zero dispatchable stories: ``factory.chain.handlers.stories_in_flight`` 

16 returns an empty list for the app AFTER subtracting every story parked 

17 in a PERMANENT-park sink (``factory.directions.tracker_issue. 

18 _story_is_resolved`` — deployed/superseded/closed/closed_by_operator/ 

19 blocked_ci_unresolved/blocked_dependency_unmet/quarantined_invalid_state, 

20 with the dependency-cap carve-out that predicate already encodes). Without 

21 this subtraction, ONE story permanently parked in e.g. 

22 ``blocked_ci_unresolved`` (absent from ``stories_in_flight``'s own, 

23 narrower terminal set — see the note below) makes the app read as 

24 "in flight" forever, silencing every future ping. See the note below on 

25 why ``stories_in_flight``, not ``factory_status._TERMINAL_STATES``, is 

26 the base source. 

27 * zero LIVE human-filed directions (see ``_has_live_human_direction``). 

28 

29The episode ENDS the first tick where either condition flips: a story gets 

30dispatched/advanced (the filtered ``in_flight`` becomes non-empty) or a human 

31files a new direction (or an existing one is still pending). Ending the 

32episode is entirely implicit — the next non-idle tick simply finds no reason 

33to ping and clears the persisted marker; there is no separate "work happened" 

34timestamp to track, because the in-flight computation and the human-direction 

35scan are themselves fresh, authoritative reads of "has anything happened" 

36every single tick. 

37 

38Exactly ONE operator ping is written per episode: the FIRST idle tick writes 

39the marker; every subsequent idle tick, while the marker is still present, is 

40a no-op for the marker/ping. A second episode (idle -> work -> idle again) 

41gets a second ping. The ``app_idle`` EVENT is a different signal with a 

42different cadence — see "Two signals, two cadences" below. 

43 

44Two signals, two cadences 

45-------------------------- 

46``app_idle`` (the event, on ``state/events/idle.ndjson``) and the operator 

47ping (the marker + ``factory inbox`` entry) look related but answer different 

48questions, and conflating them was a real bug (found in a 019 fail-silent 

49audit, corrected here — see ``STATUS.md``): 

50 

51 * The operator ping answers "has a HUMAN been notified about this episode 

52 yet" — deduplicated once per episode, because notifying the same human 

53 of the same ongoing silence every tick is the 957-fires-zero-humans 

54 failure mode this module exists to end. 

55 * ``app_idle`` answers "is the tick loop ALIVE and does it currently judge 

56 this app idle" — a liveness heartbeat 

57 ``factory.manager.detectors.stalled_stories`` consumes with a 30-minute 

58 freshness window (``idle_recently`` / ``healthy_drain``). A heartbeat 

59 that fires once and then goes quiet for the rest of a multi-hour episode 

60 reads as "not idle recently" to that consumer well before the episode 

61 actually ends — exactly backwards. So ``app_idle`` fires on EVERY idle 

62 tick, not once per episode; only the ping is deduplicated. 

63 

64Why ``stories_in_flight``, not ``factory_status._TERMINAL_STATES`` 

65-------------------------------------------------------------------- 

66The deleted ``idle.py::_stories_in_flight`` counted stories using 

67``factory_status._TERMINAL_STATES``, which additionally treats 

68``blocked_review_nonconvergent`` and ``blocked_underspecified`` as terminal 

69(so those stories did NOT count as "in flight" -> the app could read as idle 

70even while a story sat in one of those states). ``factory.chain.handlers. 

71stories_in_flight`` is narrower: it is the literal list 

72``factory.chain.orchestrator.tick`` iterates to decide what to dispatch this 

73tick (see ``orchestrator.tick``'s ``stories = H.stories_in_flight(app, db)`` 

74call). Using it here means "dispatchable work" in the ping can never disagree 

75with what the tick itself just did or didn't do — a re-derived terminal-state 

76set is exactly the kind of drift-prone duplication that caused silent- 

77detection-failure bugs elsewhere in this codebase. The tradeoff: an app whose 

78only story sits in ``blocked_review_nonconvergent`` / ``blocked_underspecified`` 

79will NOT be pinged as idle here (those states are absent from ``handlers. 

80stories_in_flight``'s terminal set, so the story still counts as "in flight"). 

81That story is not silently lost, though — it already surfaces via 

82``factory inbox``'s "Needs human action" table and ``factory why``. 

83 

84Fail-safe direction: toward silence, not noise 

85------------------------------------------------- 

86This whole module exists because a detector that fires constantly and is 

87never acted on is worse than one that occasionally stays quiet a tick too 

88long. So every ambiguous case here resolves to "don't ping": 

89 

90 * Ping-state file missing -> no active episode (normal case). 

91 * Ping-state file present and parses -> already pinged this episode, 

92 stay quiet. 

93 * Ping-state file present but UNREADABLE/CORRUPT (bad JSON, wrong shape) 

94 -> SELF-HEALED: overwritten with a valid, deliberately-suppressed marker 

95 (never a guessed fresh ping — we don't know if this is a continuing 

96 episode), and the read failure is surfaced as an error the caller can 

97 record exactly ONCE (never silently swallowed, and — since the marker is 

98 now valid — never spammed on every subsequent tick either). Before this 

99 fix the corrupt-marker path never repaired the file, so the same error 

100 recurred every tick forever; ``orchestrator.tick`` appends every 

101 ``.error`` to ``summary.errors``, and ``factory tick``'s CLI exits 1 

102 whenever that list is non-empty, so one bad marker turned into a 

103 permanent ``factory-tick@.service`` crash-loop. 

104 * Cannot determine whether a live human direction exists (DB/parse error) 

105 -> assume one exists, i.e. do not ping this tick. 

106 

107A write failure when *setting* the marker is best-effort (mirrors the 

108``idle_generator.json`` / issue-hygiene-marker precedent elsewhere in the 

109chain): the ``app_idle`` event still fires so ``stalled_stories``' consumer 

110keeps working, but a persistently failing filesystem could theoretically 

111re-ping on the next tick. That residual risk is accepted here exactly as it 

112is for the pre-existing markers this module's persistence follows. 

113"""

124@dataclass 

125class IdlePingResult: 

126 """Outcome of one idle-ping evaluation for a single app."""

128 fired: bool 

129 reason: str = ""

135def _ping_state_dir(software_factory_root: Path) -> Path: 

136 return Path(software_factory_root) / "state" / "idle_ping"

138 

139def _ping_state_path(software_factory_root: Path, app: str) -> Path: 

140 return _ping_state_dir(software_factory_root) / f"{app}.json"

143def _load_ping_state(software_factory_root: Path, app: str) -> tuple[dict[str, Any] | None, str | None]: 

144 """Read the per-app ping marker. 

145 

146 Returns ``(state, None)`` when no marker exists (no active episode) or 

147 the marker was read and parsed fine. Returns ``(None, error)`` when the 

148 marker EXISTS but is unreadable/malformed — the caller (S8 self-heal) 

149 treats this tick as "already pinged" (suppress the ping, never a guessed 

150 fresh one) and then OVERWRITES the marker with a valid one, so the SAME 

151 error is never returned twice in a row. 

152 """ 

153 path = _ping_state_path(software_factory_root, app) 

154 if not path.exists(): 

155 return None, None 

156 try: 

157 raw = path.read_text(encoding="utf-8") 

158 data = json.loads(raw) 

159 except (OSError, json.JSONDecodeError) as exc: 

160 return None, f"idle_ping state unreadable for app={app}: {exc!r}" 

161 if not isinstance(data, dict) or not isinstance(data.get("idle_since"), str): 

162 return None, f"idle_ping state malformed for app={app}" 

163 return data, None

166def _write_ping_state( 

167 software_factory_root: Path, 

168 app: str, 

169 *, 

170 idle_since: str, 

171 pinged_at: str, 

172 last_delivered_unit: str | None, 

173) -> None: 

174 """Persist the marker. Best-effort — never raises.""" 

175 path = _ping_state_path(software_factory_root, app) 

176 try: 

177 path.parent.mkdir(parents=True, exist_ok=True) 

178 path.write_text( 

179 json.dumps( 

180 { 

181 "schema_version": 1, 

182 "idle_since": idle_since, 

183 "pinged_at": pinged_at, 

184 "last_delivered_unit": last_delivered_unit, 

185 }, 

186 indent=2, 

187 sort_keys=True, 

188 ), 

189 encoding="utf-8", 

190 ) 

191 except OSError: 

192 return

195def _clear_ping_state(software_factory_root: Path, app: str) -> None: 

196 """Delete the marker (the idle episode ended). Best-effort.""" 

197 path = _ping_state_path(software_factory_root, app) 

198 try: 

199 path.unlink(missing_ok=True) 

200 except OSError: 

201 return

204def _last_delivered_unit(app: str, db_path: Path) -> str | None: 

205 """Return a short human-readable tag for the most recently touched story. 

206 

207 "Last delivered unit" is shown in ``factory inbox`` so an operator who 

208 sees a ping has SOME context on what the factory was last doing before it 

209 went quiet, without needing to run ``factory queue``. Not restricted to 

210 terminal/deployed stories: any story's most recent ``updated_at`` is a 

211 reasonable proxy for "the last thing that happened", and an app that has 

212 never had a story yet correctly returns ``None``. 

213 """ 

214 from sqlmodel import Session, select 

215 

216 from factory.chain.handlers import _engine 

217 from factory.chain.state_machine import StoryRecord 

218 

219 try: 

220 eng = _engine(db_path) 

221 with Session(eng) as session: 

222 rows = session.exec(select(StoryRecord).where(StoryRecord.app == app)).all() 

223 except Exception: # noqa: BLE001 - a DB hiccup must never crash the ping 

224 return None 

225 if not rows: 

226 return None 

227 newest = max(rows, key=lambda r: (r.updated_at or "", r.id or 0)) 

228 return f"{newest.slug} ({newest.state})"

231def _has_live_human_direction(app: str, software_factory_root: Path, db_path: Path) -> bool: 

232 """True when a human-filed direction is still pending triage/decomposition. 

233 

234 "Live" = status in ``PENDING_STATUSES`` (``created`` / ``needs-direction``) 

235 AND ``source`` resolves to one of ``approval._HUMAN_SOURCE_PREFIXES`` 

236 (operator/cli/user/human), resolved DB-first exactly the way the 

237 operator-approval gate resolves it (``watcher.pending_directions`` already 

238 applies ``hydrate_direction_source`` before returning). A direction that 

239 has been pm-validated into stories is NOT re-checked here — if it still 

240 has stories in flight, rule 1 (``stories_in_flight``) already covers it; 

241 if it doesn't, it isn't "live" work waiting on anyone. 

242 

243 Fail-safe: any lookup failure (missing DB, parse error) returns True — 

244 "assume a human direction exists" — so the ambiguous case never fires a 

245 ping, matching this module's fail-toward-silence design. 

246 """ 

247 from factory.directions.approval import _HUMAN_SOURCE_PREFIXES, direction_source 

248 from factory.directions.watcher import pending_directions 

249 

250 try: 

251 pendings = pending_directions(app, software_factory_root, db_path) 

252 except Exception: # noqa: BLE001 - fail-safe: assume live human work exists 

253 return True 

254 for d in pendings: 

255 if direction_source(d).startswith(_HUMAN_SOURCE_PREFIXES): 

256 return True 

257 return False

260def run_idle_ping_tick( 

261 software_factory_root: Path, 

262 app: str, 

263 db_path: Path, 

264 *, 

265 now: datetime | None = None, 

266) -> IdlePingResult: 

267 """Evaluate idle state for ``app``; fire the liveness event every idle 

268 tick and the deduplicated operator ping at most once per episode. 

269 

270 Caller contract: this function NEVER files a direction. It touches the 

271 ``idle_ping`` marker (deduplicating the OPERATOR ping, once per episode) 

272 and the ``app_idle`` event stream (S9: emitted on EVERY idle tick — a 

273 load-bearing liveness signal ``stalled_stories.idle_recently`` / 

274 ``healthy_drain`` consumes with a 30-minute freshness window, NOT the 

275 same thing as the deduplicated ping). It is safe to call every tick. 

276 """ 

277 from factory.chain.handlers import stories_in_flight 

278 from factory.directions.tracker_issue import _story_is_resolved 

279 from factory.manager.signals import write_event 

280 

281 root = Path(software_factory_root) 

282 moment = now or datetime.now(UTC) 

283 

284 state, corrupt_error = _load_ping_state(root, app) 

285 if corrupt_error is not None: 

286 # S8 self-heal: a corrupt/malformed marker used to return here EVERY 

287 # tick forever — never repaired, never re-checked — which (a) 

288 # suppressed the ping forever on this app and (b) appended an 

289 # "idle-ping" entry to ``summary.errors`` on every single tick. 

290 # ``factory tick``'s CLI (cli.py) raises ``typer.Exit(1)`` whenever 

291 # ``summary.errors`` is non-empty, so one bad marker turned into a 

292 # PERMANENT ``factory-tick@.service`` crash-loop (Result=exit-code on 

293 # every run, carrying no new information after the first). Repair it 

294 # now: overwrite with a valid, deliberately SUPPRESSED marker (we 

295 # don't know whether this is a continuing episode or a fresh one, so 

296 # we never guess a fresh ping) and surface the failure exactly ONCE 

297 # — this tick's ``.error`` — never again once the marker is clean. 

298 idle_since = moment.isoformat() 

299 _write_ping_state( 

300 root, 

301 app, 

302 idle_since=idle_since, 

303 pinged_at=idle_since, 

304 last_delivered_unit=_last_delivered_unit(app, db_path), 

305 ) 

306 return IdlePingResult( 

307 fired=False, 

308 reason="corrupt_state_repaired", 

309 idle_since=idle_since, 

310 error=corrupt_error, 

311 ) 

312 

313 # S8: subtract the PERMANENT-park sinks before the emptiness test. 

314 # ``stories_in_flight``'s own terminal set (see its docstring) is 

315 # narrower than the resolved-states allowlist used elsewhere (it 

316 # deliberately keeps ``blocked_review_nonconvergent`` / 

317 # ``blocked_underspecified`` "in flight" so they stay visible to the 

318 # dispatcher's own bookkeeping) — but it OMITS ``blocked_ci_unresolved``, 

319 # ``blocked_dependency_unmet`` and the other permanent sinks 

320 # ``_story_is_resolved`` treats as done. One story parked in any of those 

321 # made ``in_flight`` permanently non-empty, so the app could NEVER be 

322 # judged idle again — a single dead story silencing every future ping. 

323 in_flight = [s for s in stories_in_flight(app, db_path) if not _story_is_resolved(s)] 

324 idle_now = not in_flight and not _has_live_human_direction(app, root, db_path) 

325 

326 if not idle_now: 

327 if state is not None: 

328 _clear_ping_state(root, app) 

329 return IdlePingResult(fired=False, reason="not_idle") 

330 

331 # S9: emit ``app_idle`` on EVERY idle tick (restoring the pre-AC5 

332 # contract the deleted ``idle.py`` writer had), decoupled from the 

333 # once-per-episode operator ping below. ``stalled_stories.idle_recently`` 

334 # requires an ``app_idle`` within 30 minutes; the once-per-EPISODE 

335 # writer this module shipped with (#252) could go stale mid-episode 

336 # (measured live: last emission 03:24, next tick's read at 04:22 — 55 

337 # min stale — ``healthy_drain`` false for the whole window). The two 

338 # signals are genuinely different (a continuous liveness heartbeat vs. a 

339 # deduplicated human-facing notification) and conflating them was the 

340 # bug. 

341 # ``state["idle_since"]`` is validated as a ``str`` by ``_load_ping_state`` 

342 # whenever ``state`` is not None; the cast just tells mypy what that 

343 # validation already guarantees. 

344 idle_since = cast(str, state["idle_since"]) if state is not None else moment.isoformat() 

345 last_unit = _last_delivered_unit(app, db_path) 

346 # S8: emit the event BEFORE writing/touching the marker below — a crash 

347 # between the two used to lose the episode's ``app_idle`` silently 

348 # (marker written, event never emitted, no retry because the marker now 

349 # reads "already pinged"). 

350 write_event( 

351 "idle", 

352 { 

353 "event": "app_idle", 

354 "app": app, 

355 "idle_since": idle_since, 

356 "last_delivered_unit": last_unit, 

357 }, 

358 software_factory_root=root, 

359 ) 

360 

361 if state is not None: 

362 # Already pinged for this episode — no NEW operator ping, but 

363 # ``app_idle`` above still fired this tick (S9). 

364 return IdlePingResult( 

365 fired=False, 

366 reason="already_pinged", 

367 idle_since=state.get("idle_since"), 

368 last_delivered_unit=state.get("last_delivered_unit"), 

369 ) 

370 

371 # First idle tick of a NEW episode — fire the deduplicated operator ping. 

372 pinged_at = moment.isoformat() 

373 _write_ping_state( 

374 root, app, idle_since=idle_since, pinged_at=pinged_at, last_delivered_unit=last_unit 

375 ) 

376 return IdlePingResult( 

377 fired=True, reason="pinged", idle_since=idle_since, last_delivered_unit=last_unit 

378 )

381def active_pings(software_factory_root: Path, apps: list[str]) -> list[dict[str, Any]]: 

382 """Return ``{"app", "idle_since", "last_delivered_unit"}`` for every app 

383 currently carrying an active (already-pinged) idle episode marker. 

384 

385 Used by ``factory inbox``. Tolerant per-app: a corrupt marker for one app 

386 is skipped rather than hiding every other app's ping (mirrors the 

387 per-section try/except style the rest of ``inbox_cmd`` already uses). 

388 """ 

389 root = Path(software_factory_root) 

390 out: list[dict[str, Any]] = [] 

391 for app in apps: 

392 state, error = _load_ping_state(root, app) 

393 if error is not None or state is None: 

394 continue 

395 out.append( 

396 { 

397 "app": app, 

398 "idle_since": state.get("idle_since"), 

399 "last_delivered_unit": state.get("last_delivered_unit"), 

400 } 

401 ) 

402 return out
